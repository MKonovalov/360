<objective>
Close the CR-01 trigger-name resolution seam and the WR-02 empty-list state at the pure-logic + wrapper layer, so the form-level valueName wiring (plan 21-07) has tested seams to consume.

Purpose: GAP-1 (SET-05) — the primary picker trigger currently shows the raw model id (`claude-sonnet-4-6`) because `ModelPicker`'s trigger lookup `options.find((m) => m.id === value)` can never match a primary id that `optionsForSlot(slotIndex=-1)` excludes by design. GAP-2 (SET-06) — `data-checked={value === m.id}` can likewise never be true for the primary slot, and the anthropic primary picker (exactly 1 servable model = the primary itself) opens to an unexplained empty list. This plan extracts the name-resolution decision into a pure, unit-tested helper (`triggerLabel` — review IN-03's missing seam) and the current-selection pin decision into another (`pinnedSelection` — review WR-02's fix), then makes the wrapper consume both. The wrapper fix here PRECEDES the form-level valueName wiring (21-07, next wave) per the gap scope discipline.

Output: `triggerLabel` + `pinnedSelection` exports in model-picker-logic.ts with a pinned test suite; `ModelPicker` gains an optional `valueName` prop, its trigger resolves via `triggerLabel`, and it renders a disabled, checked "current selection" row via `pinnedSelection` (which also carries the WR-02 "only available {provider} model" explanation when the options list is empty).
</objective>
