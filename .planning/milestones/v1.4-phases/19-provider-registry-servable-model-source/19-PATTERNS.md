**Analog:** itself. The provider registry is *additive accessors over the same snapshot* — the ARCHITECTURE.md rationale (Structure Rationale) is that catalog.ts already owns model identity, so the registry stays here rather than a new `providers.ts`.

**Imports pattern** (l.1-4) — keep JSON import + derive types from it (any new `structuredOutputs` field flows into `CatalogModel` automatically):
```typescript
import catalogJson from './catalog.json';

export type ModelCatalog = { generatedAt: string; models: CatalogModel[] };
```

**Gate-as-data pattern to mirror** — `ANTHROPIC_ALLOWLIST` (l.13) is the template for `PROVIDER_GATES`. Keep the roster-verification comment block style (l.6-12 documents *why* the gate is sonnet-only — comment explains the non-obvious decision, per CONVENTIONS.md):
```typescript

```

**Existing function to RENAME (D-05)** — `getAllowlistedServableIds` (l.43-47) is the template for `getServableIdsForProvider(catalog, provider)`. Its active-rows filter (`providerID === 'anthropic' && status !== 'deprecated'`) is the shared logic; the parameterized version just takes `provider` from the caller and consults `PROVIDER_GATES[provider].allowlist`:
```typescript
export function getAllowlistedServableIds(catalog: ModelCatalog): string[] {
  return catalog.models
    .filter((m) => m.providerID === 'anthropic' && m.status !== 'deprecated')
    .map((m) => m.id)
    .filter((id): id is string => ANTHROPIC_ALLOWLIST.includes(id));
}
```

**Target shape (ARCHITECTURE.md Pattern 1, l.105-141)** — the new registry block. This is the locked design; copy verbatim, adapting names:
```typescript
export type ModelProviderId = 'anthropic' | 'openrouter';

export const PROVIDER_GATES: Record<ModelProviderId, { allowlist?: readonly string[] }> = {
  anthropic: { allowlist: ANTHROPIC_ALLOWLIST },  // sonnet-only, roster-verified (D-02)
  openrouter: {},                                  // full catalog: all active openrouter rows
};

export const SERVABLE_PROVIDERS: readonly ModelProviderId[] = ['anthropic', 'openrouter'];

export function getServableIdsForProvider(
  catalog: ModelCatalog,
  provider: ModelProviderId,
): string[] {
  const active = catalog.models
    .filter((m) => m.providerID === provider && m.status !== 'deprecated')
    .map((m) => m.id);
  const allowlist = PROVIDER_GATES[provider].allowlist;
  return allowlist ? active.filter((id) => allowlist.includes(id)) : active;
}

export function getUnionServableIds(catalog: ModelCatalog): string[] {
  return [...new Set(SERVABLE_PROVIDERS.flatMap((p) => getServableIdsForProvider(catalog, p)))];
}

// Anti-Pattern 1: MUST scope the find to the two servable providers — the
// snapshot holds dual opencode/anthropic rows for the same id and naive
// find() returns the opencode row (sorts first) for nearly every anthropic id.
export function getProviderForModelId(catalog: ModelCatalog, id: string): ModelProviderId | null {
  const row = catalog.models.find(
    (m) => m.id === id && (m.providerID === 'anthropic' || m.providerID === 'openrouter'),
  );
  return row ? (row.providerID as ModelProviderId) : null;
}
```

**D-08 field:** `CatalogModel` gains `structuredOutputs: boolean` (derived from live API `supported_parameters.includes('structured_outputs')`). Because `CatalogModel` is `(typeof catalogJson)['models'][number]`, the type updates automatically when the snapshot regenerates — no interface edit needed beyond the script's `trimRecord`. D-09's family-based default (closed-source → strict:true, open-source → strict:false) is the code-side fallback for unknown rows only; research caveat 4: derive from `supported_parameters`, never from family name (llama-3.3-70b/deepseek-v4 support it; qwen3-235b doesn't).

**Collision canary (Anti-Pattern 1 detection):** a `modelFactory` unit test asserting `instantiateModel('claude-sonnet-4-6')` dispatches to the anthropic constructor + a catalog test asserting `getProviderForModelId(fixture, 'claude-sonnet-4-6') === 'anthropic'` on a fixture that dual-lists the id.

### `src/lib/agents/modelFactory.ts` (factory — NEW)

**Analog:** the `anthropic(id)` seams it replaces — `runAgent.ts:47` (`models = [anthropic(FAST_MODEL_ID)]`) and `analyzeCompany.ts:68` (`modelChain.map((id) => anthropic(id))`). This is the ONLY module that may import provider SDKs (constraint 11).

**Import surface + module-singleton** — the singleton pattern mirrors `src/lib/sanity.ts`'s module-level client. **Two corrections vs ARCHITECTURE.md Pattern 3, per RESEARCH.md:** (a) `compatibility: 'strict'` must be passed EXPLICITLY — bare `createOpenRouter()` defaults to `'compatible'` (research caveat 2, verified `dist/index.d.ts:796-801`); (b) `apiKey` auto-loads from `process.env.OPENROUTER_API_KEY` — do NOT pass `apiKey: env.OPENROUTER_API_KEY` explicitly (research Env-key behavior; the D-11 declaration-only scope means the key may be unset, and `createOpenRouter` with no key doesn't throw — it fails at request time, which Phase 20's gate prevents):
```typescript
import { anthropic } from '@ai-sdk/anthropic';
import { createOpenRouter } from '@openrouter/ai-sdk-provider';
import type { LanguageModel } from 'ai';
import { FAST_MODEL_ID, getProviderForModelId } from '@/lib/models/catalog';
import catalogJson from '@/lib/models/catalog.json';

// Module-singleton (sanity-client pattern). 'strict' is REQUIRED for the real
// OpenRouter API — bare createOpenRouter() silently defaults to 'compatible'
// (streamOptions not sent). apiKey auto-loads from OPENROUTER_API_KEY.
const openrouter = createOpenRouter({ compatibility: 'strict' });
```

**Core dispatch pattern** (ARCHITECTURE.md Pattern 3, l.183-197) — with the D-08 per-model strict flag added. Research (l.36): runtime defaults `strict: true` when omitted, so only non-strict models need the option; never a global `strict: false`:
```typescript
export function instantiateModel(id: string): LanguageModel {
  const provider = getProviderForModelId(catalogJson, id);
  if (provider === 'anthropic') return anthropic(id);
  if (provider === 'openrouter') {
    const row = catalogJson.models.find((m) => m.id === id);
    // D-08: only opt out of strict for models whose snapshot flag says the
    // upstream provider doesn't advertise structured_outputs. Omitted option =
    // strict:true (SDK default). NEVER a global strict:false.
    return row?.structuredOutputs === false
      ? openrouter(id, { structuredOutputs: { strict: false } })
      : openrouter(id);
  }
  throw new Error(`unsupported provider for model ${id}`); // unreachable post-gate; fail loud
}

export function instantiateChain(ids: string[]): LanguageModel[] {
  return ids.map(instantiateModel); // FAL-01: mapped ONCE at entry, never per attempt
}

export function defaultChain(): LanguageModel[] {
  return [openrouter('anthropic/claude-sonnet-4.6')]; // D-07 — see flag below
}
```

> **⚠ Planner decision needed — `defaultChain()` target.** CONTEXT D-07 (locked) names `defaultChain()` as a consumer of the OpenRouter default primary `anthropic/claude-sonnet-4.6`. ARCHITECTURE.md Pattern 3 (l.195) sketches `return [anthropic(FAST_MODEL_ID)]` (REG-05 default stays anthropic). These conflict. The CONTEXT decision governs; the research sketch predates it. Resolution must also account for the Phase 19 env gate (`analyzeCompany.ts:44` still checks only `ANTHROPIC_API_KEY` until Phase 20) — a no-settings run through an OpenRouter `defaultChain()` would pass the gate on the Anthropic key but hit OpenRouter. Pick the locked D-07 reading and note the Phase 20 gate implication, or surface the conflict.

**Error handling:** throw on unknown provider = fail-loud backstop for catalog drift; unreachable in practice because union validation + chain resolution already exclude non-servable ids (ARCHITECTURE.md l.203).
