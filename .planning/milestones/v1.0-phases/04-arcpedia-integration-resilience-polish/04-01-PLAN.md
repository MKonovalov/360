<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Next.js Server Component (`CompanyDetail`/`PersonaDetail`) → Arcpedia (`arcpedia.arclumen.de`, external, Cloudflare Access–gated) | Outbound HTTPS GET; only `entityName` (an internal DB field, `company.name`/`persona.name`) and Arcpedia's own response (`slug`/`title`/`snippet`) cross this boundary |
| Arcpedia JSON response → rendered JSX | Third-party, LLM-synthesized content rendered into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `fetchArcpediaArticles`'s `q` query-string construction | mitigate | `entityName` is `encodeURIComponent()`-encoded before interpolation; `entityName` always originates from `company.name`/`persona.name` (an internal DB column read server-side), never directly from an incoming HTTP request parameter — no SSRF/injection path from an untrusted caller |
| T-04-02 | Tampering | Outbound `href` built from Arcpedia's `article.slug` | mitigate | `encodeURIComponent(article.slug)` applied before constructing the link — defense-in-depth even though Arcpedia's own `SAFE_SLUG_RE` already constrains the slug's character set |
| T-04-03 | Information Disclosure | `ARCPEDIA_ACCESS_CLIENT_ID`/`ARCPEDIA_ACCESS_CLIENT_SECRET` | mitigate | Declared unprefixed (never `NEXT_PUBLIC_`) and `.optional()` in `src/lib/env.ts`; used only inside a Server Component's `fetch()` call, never a Client Component; `fetchArcpediaArticles`'s catch-all `catch { return []; }` never logs the caught error, preventing accidental credential/response-body leakage into server logs |
| T-04-04 | Tampering / Information Disclosure | Rendering `article.title`/`article.snippet` | mitigate | Rendered as plain JSX text (React auto-escapes); never via `dangerouslySetInnerHTML` |
| T-04-05 | Denial of Service | Arcpedia fetch hanging or slow, blocking the whole detail-pane render | mitigate | `AbortSignal.timeout(5000)` bounds worst-case wait; the DB-fetch try/catch is a fully independent failure domain (D-10), so a slow/hung Arcpedia call can never surface as "Couldn't load company/persona" — only the Related Knowledge section is absent |
| T-04-06 | Tampering | ARCP-02 — no write/mutating call ever issued to Arcpedia | mitigate | `fetchArcpediaArticles` never sets a `method` key on its single `fetch()` call (GET is the implicit default); Task 1's acceptance criteria include a `grep -c "method:"` == 0 check against the file, giving a durable, re-runnable proof this holds |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed this plan (native `fetch`, `AbortSignal.timeout`, and the already-installed `zod` only) — Package Legitimacy Gate not triggered per 04-RESEARCH.md's Package Legitimacy Audit |

</threat_model>
