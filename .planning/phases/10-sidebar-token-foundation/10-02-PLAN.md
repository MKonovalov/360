<objective>
Extract active-route detection into a pure, boundary-guarded `getActiveNavKey(pathname)` function in `src/lib/nav.ts` with an 11-case Vitest regression suite in `src/lib/nav.test.ts` — the QLTY-01 mandated lock so a drive-by "simplification" of the `/companies/[id]` highlight can never silently break.

Purpose: The current inline expressions in `app-sidebar.tsx:39,48,57,66` use bare `pathname.startsWith('/companies')` — correct today, but a future "simplification" to exact equality would silently break the detail-page highlight, and a sibling prefix like `/companies-archive` would false-positive. This plan converts that risk into a permanent test. The function is shipped tested but intentionally UNWIRED — Phase 11 swaps the four consumer expressions (roadmap SC #5, UI-SPEC line 178).

Task order is function-first (not test-first RED) by design: `tsconfig.json` includes `**/*.ts` (line 27) and `next build` type-checks test files, so a RED-state `nav.test.ts` importing a not-yet-existing `./nav` would spuriously fail the parallel Plan 10-01 build gate in Wave 1. Both Wave-1 plans therefore never expose a red tree. The test contract is fully specified before implementation regardless (UI-SPEC §QLTY-01 — 11 enumerated inputs).

Output: `src/lib/nav.ts` + `src/lib/nav.test.ts`. Nothing else changes. `app-sidebar.tsx`, `sidebar.tsx`, and `package.json` remain untouched.
</objective>
