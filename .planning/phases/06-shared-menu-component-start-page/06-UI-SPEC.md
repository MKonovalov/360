# Phase 6 — UI Design Contract

> Visual and interaction contract for the Shared Menu Component + Start Page (a new dashboard landing page at `/`, plus a shared "Menu" dropdown affordance on both explorers' list pages and detail panels). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Inheritance notice:** The design system (shadcn preset, typography scale, spacing scale, color palette, copywriting voice) is inherited verbatim from `02-UI-SPEC.md`/`03-UI-SPEC.md` (Company/Persona Explorers) and `05-UI-SPEC.md` (Layout Rework), confirmed against currently-shipped code (`src/app/globals.css`, `components.json`, `src/components/ui/*.tsx`, `src/components/companies/*.tsx`). This document does **not** re-derive spacing/typography/color — it adds the two genuinely new surfaces this phase introduces: (1) the Start Page's stat-card/list-widget composition, and (2) the shared `DropdownMenu` component and its two placement contracts (MENU-01 list-page, MENU-02 detail-panel).

## Spacing Scale

Inherited verbatim from `02-UI-SPEC.md`/`03-UI-SPEC.md`/`05-UI-SPEC.md`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding, Menu-trigger-to-Close-button gap (new this phase, detail panel) |
| sm | 8px | Compact element spacing (dropdown item internal padding, stat-card icon-to-label gap) |
| md | 16px | Default element spacing (dashboard section internal padding, list-row padding) |
| lg | 24px | Section padding (stat card `p-6`, widget card padding) |
| xl | 32px | Layout gaps (page-level `p-8` container padding — unchanged) |
| 2xl | 48px | Major section breaks (between dashboard row-groups: stat cards / lists / needs-attention) |
| 3xl | 64px | Page-level spacing |

Exceptions (carried forward, plus new this phase):
- Detail-panel Menu trigger + Close button tap target: **32px** (`size-8`, shadcn `Button` `size="icon"`), same as the existing `ExplorerCloseButton` — unchanged sizing convention, now used twice in the same button group.
- Dashboard stat-card grid gap: **16px** (`gap-4`), consistent with `md` token.
- Empty/error-state card minimum height: **192px** (`min-h-48`), unchanged — reused for each dashboard widget's own empty/error state (see Copywriting Contract).

## Typography

Inherited verbatim — no new typographic role is introduced by the Start Page or Menu:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | Regular (400) | 1.5 |
| Label | 12px | Regular (400) | 1.4 |
| Heading | 18px | Semibold (600) | 1.2 |
| Display | 24px | Semibold (600) | 1.2 |

Usage this phase:
- Stat-card big number → **Display** (24px/600), same role as an entity name in a detail-panel header.
- Stat-card caption ("Companies" / "Personas" / "Active Signals") → **Label** (12px/400, slate-500), same role as column headers/badges.
- Dashboard section headings ("Recent Signals", "Recently Viewed", "Needs Attention", "Signal Breakdown") → **Heading** (18px/600), same role as detail-panel section headers (Firmographics, Tech Stack, etc.).
- List-row primary text (company/persona name, dropdown menu item label) → **Body** (14px/400).
- List-row secondary text (source · date, "viewed 2 days ago") → **Label** (12px/400, slate-500).

No third weight, no fifth size introduced.

## Color

Inherited verbatim (slate neutrals + indigo-600 accent + amber signal badges):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / slate-50 (`#f8fafc`) | Page background, stat-card surface, widget-card surface |
| Secondary (30%) | slate-100 / slate-200 (`#f1f5f9` / `#e2e8f0`) | Sidebar background, card/table borders, dropdown-menu content background+border, dropdown item hover background |
| Accent (10%) | indigo-600 (`#4f46e5`) | Focus rings, inline text links (Company name links from Recent Signals/Recently Viewed/Needs Attention rows), the new "Start" sidebar nav item's active-state highlight (mirrors existing Companies/Key Personas `data-active:bg-indigo-50 data-active:text-indigo-600` treatment) |
| Destructive | Not applicable this phase | No destructive actions exist in Phase 6 — Import/Analyze are inert placeholder menu items, no delete/edit affordance anywhere |

Accent reserved for: focus-visible rings on interactive elements (rows, buttons, links), inline text links to Company/Persona detail, and the active sidebar nav-item highlight. **Never** apply accent to: the Menu trigger icon/chevron (stays slate-500, ghost-button default), the stat-card numbers (slate-900, not accent — these are informational, not interactive), or the signal-type breakdown's badges (stay amber-100/amber-800 per the existing `SignalBadge` lock — do not introduce per-type hues here either, confirmed by reading `src/components/companies/signal-badge.tsx`'s explicit "one neutral badge style" comment).

**New this phase — zero new hues, one confirmed reuse:**
- Signal-type breakdown widget badges reuse `SignalBadge` verbatim (amber-100/amber-800) — the 4 named signal types (`cost_pressure`, `immature_gbs_org`, `new_cfo_or_gbs_head`, `transformation_announcement`) are already labeled by that component; do not create a second badge component for this widget.

## Interaction Contract (new this phase)

**Focal point:** On the Start Page, the primary visual anchor is the 3-stat-card row (Company/Persona/Signal counts) at the top — the first thing a viewer's eye lands on, establishing scale before the eye moves down into the list widgets. On the explorers, the Menu trigger is a secondary anchor (never competing with the row/detail-panel content it sits above) — it should read as a quiet, always-available utility control, not a call-to-action.

### Start Page layout (fixed, non-customizable per PROJECT.md's explicit Out-of-Scope)

| Region | Contract |
|--------|----------|
| Page container | `flex flex-col gap-8 p-8` — mirrors `/companies`/`/personas`' existing `p-8` page padding (consistent gutters across all three main routes) |
| Row 1 — Stat cards | `grid grid-cols-1 gap-4 sm:grid-cols-3` — 3 cards: Companies, Personas, Active Signals. Each card: `rounded-lg border border-slate-200 bg-white p-6` (same border/radius language as existing empty-state cards), containing a Label-style caption above a Display-style number. |
| Row 2 — Recent Signals + Recently Viewed | `grid grid-cols-1 gap-4 lg:grid-cols-2` — two widget cards side by side on wide viewports, stacked on narrow. Each: `rounded-lg border border-slate-200 bg-white p-6`, Heading-style title, then a `space-y-2` list of rows (max 5 items shown for Recently Viewed per D-05; Recent Signals shows newest-first, no fixed cap specified in requirements — default to 5 for visual parity with Recently Viewed unless research/planning finds a reason to diverge). |
| Row 3 — Needs Attention + Signal Breakdown | `grid grid-cols-1 gap-4 lg:grid-cols-2` — same card treatment as Row 2. Needs Attention lists Companies (name + their high-strength `SignalBadge`s + "not reviewed" implied by presence in this list — no explicit "X days" copy needed since the threshold is a query filter, not a displayed value). Signal Breakdown lists the 4 signal types each as `SignalBadge` + count (Body-size, slate-900, right-aligned) in a `space-y-2` list — no chart/bar visualization (Out of Scope). |
| List-row link target | Every Company/Persona name in Recent Signals / Recently Viewed / Needs Attention is a text link (indigo-600, matching existing Arcpedia/persona-link convention) to `/companies?selected=<id>` or `/personas?selected=<id>` — reuses Phase 5's `?selected=` deep-link convention directly; no new route. |

### Menu component (shared, both placements)

| Behavior | Contract |
|----------|----------|
| Underlying primitive | shadcn `DropdownMenu` / `DropdownMenuTrigger` / `DropdownMenuContent` / `DropdownMenuItem` (official registry, installed fresh this phase) — one shared composed component (e.g. `src/components/explorer/explorer-menu.tsx`) parameterized by which item(s) it renders, reused by both list-page and detail-panel placements. |
| MENU-01 — List-page Menu | A **labeled** `Button variant="outline"` (not ghost — this is a standalone top-right element per D-09, not paired with another icon button) reading **"Menu"** with a trailing `ChevronDownIcon` (rotates on open, mirrors `select.tsx`'s existing chevron-rotation pattern). Positioned top-right, in its own row **above** the table, visually separated from the `CompanySearchInput`/`CompanyFilters` row directly below it (D-09 — list-narrowing controls stay visually distinct from list-acting controls). Layout: `flex items-center justify-between` wrapping the existing page heading area (or a new bare row if no heading currently exists) with the Menu button as the trailing element. |
| MENU-02 — Detail-panel Menu | An **icon-only** `Button variant="ghost" size="icon"` with `EllipsisVerticalIcon`, `aria-label="Menu"` — positioned **immediately left of** `ExplorerCloseButton`, both wrapped in a shared `absolute top-3 right-3 flex items-center gap-1` container (replacing `ExplorerCloseButton`'s current standalone `absolute top-3 right-3` — the Close button's own class becomes just `flex items-center` inside the new wrapper, no visual change to its own appearance or 32px tap target). |
| Dropdown content | `DropdownMenuContent align="end"` (opens leftward/downward from the trigger, never clipped at the viewport's right edge) containing `DropdownMenuItem`s for "Import" (list-page) or "Analyze" (detail-panel) — both `disabled` this phase per the Copywriting Contract above. |
| Focus/keyboard | Inherited free from Radix's `DropdownMenu` primitive (Escape closes, Arrow keys navigate items, Enter/Space activates) — no custom keyboard handling needed, unlike Phase 5's bespoke roving-tabindex (that pattern is specific to the accordion table, not reused here). |
