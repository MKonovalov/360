## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Future Server Action (Phase 31/32) → these query modules | Query functions trust their caller to have already run `requireStaffAccess()`; they perform no auth check themselves |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-02 | Tampering / Repudiation | `deletePracticeArea`, `deleteDomain`, `deleteBuyerRole` | mitigate | `hasXDependents()` pre-check pattern (silent-cascade-delete threat, per 30-RESEARCH.md Security Domain) — every delete function returns a discriminated-union `{ ok: false, reason: 'has_dependents' }` instead of deleting when dependents exist; Postgres FK `ON DELETE RESTRICT` (Drizzle default, no `onDelete` override anywhere) is the hard backstop if the pre-check is ever bypassed |
| T-30-03 | Repudiation | `insertPracticeArea`/`insertDomain`/`insertBuyerRole` | accept | `created_by`/`updated_by` are `NOT NULL` at the schema level (Plan 01) — these functions accept them as required parameters, no further mitigation needed at this layer |
</threat_model>
