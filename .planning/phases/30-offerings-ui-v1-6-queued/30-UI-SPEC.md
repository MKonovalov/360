## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 29, reused verbatim for chrome consistency across sibling `Manage` screens:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (e.g. `gap-1`), chevron/expand-icon padding, rank-badge internal padding |
| sm | 8px | Compact element spacing (`gap-2`), Sheet footer button gap, up/down reorder-button gap |
| md | 16px | Default element spacing (`gap-4`, filter-bar item gap, Sheet header/footer padding `p-4`), indent step per hierarchy nesting level (Practice Area → Domain → Offering, `pl-4` per level) |
| lg | 24px | Card/list container padding on empty states (`p-8` rounds to 32 — see exception), section padding, Matrix tab's per-Domain section header top margin |
| xl | 32px | Page-level vertical stack gap (`p-8` wrapper — see exception) |
| 2xl | 48px | Major section breaks (page title → tab content gap, `gap-12` — see exception) |
| 3xl | 64px | Page-level spacing (unused this phase) |

Exceptions (both pre-existing house conventions, reused verbatim — do not invent new arbitrary values):
- Empty-state / error-card padding is `p-8` (32px) — matches `company-list.tsx`/`reviews/page.tsx`/Phase 29's Signals screen exactly.
- Page title → content gap is `gap-12` (48px) — matches `reviews/page.tsx`'s / `signals/page.tsx`'s `<div className="flex flex-col gap-12 p-8">` wrapper exactly; reuse this exact wrapper for the `/offerings` page shell.
- Hierarchy nesting indent (`pl-4` per level, 16px) is new to this phase (no prior hierarchy UI exists) but stays on the 8-point scale — do not use a non-multiple-of-4 indent.

| Role | Value | Usage |
|------|-------|-------|

| Secondary (30%) | `#e2e8f0` (Tailwind `slate-200`, matches existing `border-slate-200` house convention) for borders/dividers/nesting-level guides; `#f7f7f7` (`oklch(0.97 0 0)`, `--muted`/`--secondary`) for Matrix `TableHeader` background, Domain section-header row background, and row-hover state | Hierarchy row borders (`border border-slate-200 bg-white`, verbatim `company-list.tsx`/Phase 29 pattern), Domain-group header row in the Matrix tab (subtle `bg-muted` band to separate Design/Build/Run sections without a new color), `TableRow` hover (`hover:bg-muted/50`, vendored default — do not override) |
| Accent (10%) | `#4f46e5` (Tailwind `indigo-600`, existing house link/interactive color — used in 13+ other files incl. `review-queue.tsx`, and Phase 29's Tabs indicator) | Reserved ONLY for: (1) the active tab's label + underline indicator in the Service Portfolio / Matrix `Tabs` switcher — same reservation as Phase 29's Signals tabs, kept identical for cross-screen consistency. NOT used for CTA buttons, row text, rank numbers, or the reorder/expand icons. |
| Destructive | `#dc2626`-range (`oklch(0.577 0.245 27.325)`, `--destructive` token) | Reserved for the guarded hard-delete action ONLY (`deleteX` Server Actions on Practice Area/Domain/Offering/Buyer Role, gated by the dependents check) — this is the one truly destructive, non-reversible action this phase exposes. The Delete button/menu item itself may use `variant="destructive"`/red text, but the confirmation Dialog's confirm button (D-10) uses `variant="default"` (near-black) because the dialog's job is to inform/block, not to be the point of no return styling twice over — matches `ArchiveSignalDialog`'s existing precedent of reserving red for the trigger, not the confirm step. |

**Archive vs. Delete color distinction (new to this phase, extends Phase 29's rule):**
- **Archive** (status flip to `retired`, on Practice Area/Domain/Offering — reversible): never destructive-styled. `Button variant="outline" size="sm"` row trigger, `Dialog` confirm uses `variant="default"` — byte-identical to `ArchiveSignalDialog`'s pattern.
- **Delete** (guarded hard delete, on all four entity kinds incl. Buyer Role which has no status column — potentially irreversible if the dependents check passes): trigger button/menu item MAY use `variant="destructive"` (red) since this is genuinely irreversible when it succeeds, but stays a secondary/overflow action per D-10 (never the primary row action — Archive is primary for the three status-bearing entities; Buyer Role's only removal path IS delete, since it has no status field, so its row exposes Delete directly, still `variant="destructive"` on the trigger, `variant="default"` on the confirm dialog's actual confirm button per the row above).

Primary CTA color note (not accent, not destructive): "New Practice Area" / "New Domain" / "New Offering" / "Add Trigger" / "New Buyer Role" buttons use the vendored `Button` `variant="default"` — `bg-primary` (near-black, `oklch(0.205 0 0)`), matching the house convention already used for CTAs in `review-queue.tsx` and Phase 29's Signals screen. This keeps the 10% accent slice reserved exclusively for the tab indicator, per the reserved-for list above.

## Row Anatomy / Layout Notes (non-template, executor-facing)

- **Visual anchor:** The Service Portfolio hierarchy list is the primary focal point on load; the Matrix table is the secondary tab.
- **Page shell:** `<div className="flex flex-col gap-12 p-8">` wrapping `<h1>Offerings</h1>` + `Tabs` — exact reuse of `signals/page.tsx`'s wrapper, byte-identical to Phase 29.
- **"Manage Buyer Roles" button placement:** rendered on BOTH tabs (Service Portfolio and Matrix), top-right of the tab content area, `variant="outline"` (not the primary CTA — it opens a lookup Sheet, not a create form for THIS tab's primary entity) — per D-05.

### Service Portfolio tab (new pattern — no prior analog in this app)

- **Hierarchy list container:** `rounded-lg border border-slate-200 bg-white` wrapping the nested list — exact reuse of `company-list.tsx`/Phase 29's container treatment.
- **Row anatomy per level:** `ChevronRight`/`ChevronDown` (16px, `text-slate-400`) → entity name (Body, 14/400) → inline `Badge` for status (`active`/`draft`, or `active`/`draft`/`retired` for offerings) → trailing right-aligned action cluster: `ArrowUp`/`ArrowDown` (icon buttons, `variant="ghost" size="icon"`) → `Edit` (`variant="outline" size="sm"`) → `Archive` (`variant="outline" size="sm"`, Practice Area/Domain/Offering only — all three have a `status` column) → overflow `MoreVertical` → `Delete…` (red, dependents-gated).
- **Nesting indent:** each level indents `pl-4` (16px) from its parent — Practice Area rows at `pl-0`, Domain rows at `pl-4`, Offering rows at `pl-8`. Collapsed by default below the Practice Area level (Domains/Offerings load lazily or are pre-fetched but hidden — planner's call on data-fetch strategy, not a visual requirement).
- **"New Domain"/"New Offering" CTAs:** appear as the LAST row inside an expanded parent's child list (e.g. a "+ New Offering" row styled as a dashed-border ghost row, `variant="ghost"` button spanning the row), not as a floating action button — keeps the create affordance co-located with its context, same principle as inline "+ add" rows elsewhere.
- **Offering edit Sheet — field order:** Name → Practice Area → Domain (optional) → Offer Type → Description → Commercial Model Text → ranked Buyer Roles (picker, D-04) → Status → (read-only) Linked Signals section (D-09, bottom of the Sheet, below the Save/Cancel footer's content but still inside `SheetContent`, visually separated by a `Separator`).
- **Ranked Buyer Roles picker (D-04):** extends `LinkedOfferingsPicker`'s checkbox-in-`ScrollArea` shape — checking a role appends it to the end of the ranked list below the checkbox list; the ranked list renders as numbered rows ("1. CFO") each with `ArrowUp`/`ArrowDown` + an unchecking "×"/remove control that also unchecks the source checkbox. Only 5 roles exist — no search input.

### Offering × Trigger × Buyer Matrix tab (D-08)

- **Filter bar:** single `Select` (Practice Area, defaults to GBS per OFR-05/spec §4.3) — reuses `EnumFilterSelect`'s nuqs `useQueryState` + `{ shallow: false }` pattern verbatim from `signal-filters.tsx`.
- **Table structure:** one `Table` with `TableRow` domain-header separators — a full-width `TableCell` (`colSpan` across all columns) styled `bg-muted font-semibold text-[14px]` reading "Design" / "Build" / "Run" — chosen over separate `Table` instances per domain (denser, single scroll context, matches spec §4.3's "grouped by Domain section headers" language most literally).
- **Columns:** Offering name → Trigger(s) → Primary Buyer(s) → Commercial Model.
- **Trigger cell:** comma-or-line-separated list of trigger chips (`Badge variant="outline"`, each with an inline "×" remove), plus a trailing "+ Add trigger" ghost button that opens the `Popover` form (single `Input` for `trigger_text` + Save/Cancel, per D-08).
- **Primary Buyer(s) cell:** ranked, comma-separated "1. CFO, 2. Head of GBS" text (read view) that opens the SAME ranked Buyer Roles picker as the Offering form (D-04) in a `Popover` when clicked, for inline editing without navigating to the Sheet.
- **Commercial Model cell:** plain truncated text (no edit affordance on the Matrix tab — editing Commercial Model Text stays in the Offering Sheet, per D-08's "editable inline or via a side drawer" — this phase chooses the Offering Sheet as the edit surface for that one field, keeping the Matrix row edit surface limited to Triggers + Buyers as the two collaborative/frequently-updated fields).

### Buyer Role lookup panel (D-05)

- **Surface:** `Sheet` (`side="right"`, default `sm:max-w-sm` — a simple name+description list, does not need the wide variant).
- **Row anatomy:** name (Body, 14/600 — the one place `font-semibold` is used at body size, to visually anchor each role as a distinct list item) → description (Label, 12/400, `text-slate-500`) → trailing `Edit` (`variant="ghost" size="icon"`, pencil icon, `aria-label="Edit {role name}"`) → `Delete` (`variant="ghost" size="icon"`, trash icon, red on hover, `aria-label="Delete {role name}"`) → dependents-gated confirmation per D-10.
- **Create:** a "New Buyer Role" button at the top of the panel opens a nested small form (inline expansion at the top of the list, or a second small `Sheet`/`Dialog` layered on top — Claude's Discretion left open in `30-CONTEXT.md`; **decided here: inline expansion** — a `name` + `description` `Input`/`Textarea` pair that slides open above the list when "New Buyer Role" is clicked, avoiding Sheet-over-Sheet stacking).

### Delete-guard dialog (D-10)

- Shares the `Dialog` primitive with `ArchiveSignalDialog` but is a distinct component (`DeleteGuardDialog` or similar) with THREE render states driven by the Server Action's discriminated-union result: (1) pre-confirm ("Delete this X? This action cannot be undone." + red `Delete` confirm), (2) blocked-after-attempt (`{ok:false, reason:'has_dependents'}` → replaces the confirm button with a "Close" only, shows the blocking copy from the Copywriting Contract), (3) success (dialog closes, `router.refresh()` — same pattern as `ArchiveSignalDialog`).
