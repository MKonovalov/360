## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Client (form submit) → Server Action | Untrusted `unknown` input crosses here for every create/update action |
| Server Action → query module | Trusted, typed calls only after zod validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-02-01 | Spoofing/Elevation of Privilege | Every exported action in offerings.ts/buyerRoles.ts | mitigate | `requireStaffAccess()` is the unconditional first statement in every action — verified by the "staff-gate-first ordering" test case per action, matching signals.ts's `invocationCallOrder` assertion pattern exactly. No action skips this call. |
| T-30-02-02 | Tampering | zod input validation on create/update actions | mitigate | Every `unknown` input is `safeParse`'d against a schema before any DB write; a failed parse returns `invalid_input` before `insertX`/`updateX` is ever called (test-verified: `insertX` `not.toHaveBeenCalled()` on invalid input) |
| T-30-02-03 | Tampering | `sortOrder` — deliberately NOT accepted from client input | mitigate | Create actions compute sortOrder server-side by counting existing sibling rows; a malicious client cannot inject an arbitrary sortOrder value to reorder other users' rows without going through the dedicated `reorderXAction`, which itself requires staff auth |
| T-30-02-04 | Repudiation/Integrity | Delete-guard business rule (DATA-10/OFR-08) | mitigate | `deletePracticeAreaAction`/`deleteDomainAction`/`deleteBuyerRoleAction` never re-implement the has_dependents check — they pass the query-layer's pre-checked discriminated-union result straight through unmodified, so the guard cannot silently regress if this file is edited later without touching the query layer |
| T-30-02-05 | Information Disclosure | Catch-all error branches | accept | Every catch returns the generic `{ ok: false, reason: 'action_failed' }` — no raw error message, stack trace, or DB detail is ever returned to the client, matching signals.ts's existing precedent |
</threat_model>
