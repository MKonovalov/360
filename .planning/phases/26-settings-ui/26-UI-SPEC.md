## Color

**Unchanged from Phase 21 — inherited verbatim.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) | Page background, card surface |
| Secondary (30%) | `slate-50`/`slate-100`/`slate-200`/`slate-500` | Wells, dividers, borders, all muted/caption text (4.73:1 AA on white) |
| Accent (10%) | `slate-900` (`--primary` token) | Page H1, card titles, **Save changes** button only |
| Destructive | `red-600` | Stale-model hints, error copy — destructive semantics only |
| Warning | `amber-700` | High-cost row cost captions only (`costInput >= 50`) — 5.03:1 AA |

Accent reserved for: page H1, card titles, Save changes button. **Not** used for: provider badges, endpoint captions, Hermes captions, or picker rows.

**New this phase — explicitly NOT a new color:** the endpoint caption (`· Zen`/`· Go`) and the Hermes capability caption (`· chat/reasoning-tuned`) both render in the standard `text-slate-500` caption color, matching every other caption part (suffix labels, family subtitles). D-26-06 confirms badges stay the uniform `secondary` variant for all 4 providers — no per-provider tint, ever (same rule as Phase 21's D-21-09, now covering 2 more providers).

**D-26-05 resolution (cost caption on OpenRouter Hermes mirror rows) — CORRECTED post-research, locked in CONTEXT.md:** the original premise ("mirror rows carry no cost data") was verified false — the live snapshot shows real non-zero cost on both mirrors (`nousresearch/hermes-4-70b` via openrouter: $0.13/$0.4 per MTok; `-405b`: $1/$3 per MTok). The corrected, locked rule: **mirror rows show their real cost caption**, identical treatment to native NousResearch rows, same `amber-700`/`slate-500` threshold rule as every other row (`isHighCost` unchanged). No suppression logic — this is a straightforward "no special case" outcome, not new color/threshold work.

## Row Anatomy (model picker rows) — EXTENDED

Prescriptive row structure inside `CommandItem`, extending Phase 21's anatomy with the new caption parts:

```
Line 1: [Badge provider]?  {model name} {suffix label}?  {endpoint · suffix composite}?  · {cost caption}
Line 2: {family}?   (muted 12px caption, only when family is non-empty)
```

**Caption-slot composition order (D-26-01, locked):**
1. Endpoint label (`Zen`/`Go`) — FIRST, only for opencode-scoped rows (`endpoint !== null`)
2. Suffix label (`~latest`/`:free`) — SECOND, only when applicable
3. Cost caption — LAST (unchanged position from Phase 21), `amber-700` when `costInput >= 50` else `slate-500`

No live opencode row currently has BOTH an endpoint AND a suffix simultaneously (RESEARCH verified: 0 opencode ids start with `~` or end with `:free`) — the compound case (`· Zen · free tier — 50 req/day`) needs a synthetic test fixture, not committed-snapshot data, to prove the ordering. Implement the composition function generically regardless (do not special-case "endpoint OR suffix, never both").

**Hermes capability caption slot:** renders in the SAME caption position as the suffix label (both are "id/provider-derived descriptor" captions) — `· chat/reasoning-tuned`, keyed on the trimmed row's `providerID === 'nousresearch'`. Since no id currently carries both a suffix AND the Hermes caption (Hermes ids never start with `~` or end with `:free`), no compound-ordering rule is needed for this pairing — but if the fixture ever grows one, endpoint/suffix/hermes captions all join with `·` in the order encountered (endpoint → suffix → hermes), consistent with D-26-01's stated principle (identity cue first, descriptive context after).

**Provider badge placement:** unchanged from Phase 21 — union fallback pickers show row badges (search results mix providers); the primary picker is provider-scoped and omits row badges (the provider is stated by the selector + section header + trigger badge). D-26-06 applies: badges are provider-only text, never composited with endpoint (`OpenCode · Zen` as a single badge is explicitly rejected — endpoint stays in the caption slot, badge stays in the badge slot, one source per slot).

**Search index (D-26-03, NEW):** `searchValue()` composes `[id, name, family, endpoint ?? ''].filter(Boolean).join(' ').toLowerCase()` — the raw lowercase token (`'zen'`/`'go'`), not the capitalized label, joins the existing id+name+family search string. Typing "go" must filter to Go-endpoint rows in both the primary (opencode-scoped) and union (fallback) pickers.

**Saved-chain recap (D-26-02, NEW):** each recap entry (`{badge} {name}`) gains an inline endpoint caption when `resolved?.endpoint` is non-null, using the SAME 12px/400/slate-500 caption style as picker rows: `{badge} {name} · {endpointLabel}`. This closes the "disambiguate Zen vs Go after Save, not just inside the pickers" requirement.

## Interaction Contract

### AI Provider selector (SET-01) — verify-only, no new interaction
4 always-valued entries render in `SERVABLE_PROVIDERS` order (Anthropic, OpenRouter, NousResearch, OpenCode) — already functionally satisfied by Phase 21/23's generic `Select` + registry-driven `PROVIDER_NAMES` map (RESEARCH confirmed: zero hardcoded branch, `providerName()` already 4-entry since Phase 23 commit `81deccb3`). This phase adds a 4-provider fixture to the existing unit tests to close the verification gap (RESEARCH Pitfall 6) — no new UI behavior.

### Provider switch → primary refresh (SET-02) — verify-only, no new interaction
Selecting a provider refreshes the Primary picker's option set from `servableByProvider[provider]` — already generic (`primaryAfterProviderSwitch` in `model-picker-logic.ts` takes any `Record<ModelProviderId, ServableModel[]>`). New: the reset-hint copy branches on whether the switch is the `claude-sonnet-4-6`/opencode collision case (D-26-09 corrected copy above) vs. the standard case (unchanged Phase 21 copy). Fallbacks preserved verbatim on switch (D-21-02, unchanged).

### Primary trigger badge (SET-05, D-26-11) — THE REAL FIX, new interaction correctness
**Bug (verified, `model-settings-form.tsx:258`):** the primary picker's closed-trigger badge currently reads `badge={provider}` — the raw dropdown `useState` value — instead of the row's true resolved provider. For the 2 verified 4-provider collisions (`claude-sonnet-4-6`: anthropic vs opencode; the 2 hermes ids: nousresearch vs openrouter), the naive dropdown-provider badge and the actual runtime-routing provider can diverge, misleading staff about which API key/provider will actually serve the request.

**Fix (locked, mirrors the already-correct fallback-picker pattern at line 308):**
```
badge={unionServableModels.find((m) => m.id === primary)?.providerID ?? provider}
```
The `?? provider` fallback preserves current behavior for the empty/in-progress and non-colliding cases. Extract into a small named pure function (`resolveBadgeProvider` or equivalent) in `model-picker-logic.ts` so it gets unit coverage — the project convention is "pure logic module is the testable surface, components are never unit-tested."

**All other badge sites are already correct** (fallback triggers, saved-chain recap, union list rows) — this is the ONE site needing the fix, not a systemic badge rewrite.

### Model pickers — extended caption rendering, same interaction shell
- **Primary picker**: options = `servableByProvider[provider]`. NEW: opencode-scoped rows render the endpoint caption; nousresearch-scoped rows render the Hermes capability caption.
- **Fallback pickers**: options = union servable list, grouped by all 4 provider sections (structurally already generic per D-21-08 — `groupByProvider` buckets by whatever `providerID` values are present, no hardcoded 2-provider assumption). NEW: same caption additions as the primary picker, applied per-row regardless of which picker renders it (both consume the same `trimRow`-derived `ServableModel[]`, so the `endpoint` field flows through automatically once derived once in `page.tsx`).
- **Sparse-provider pickers (NousResearch 2 rows, Anthropic 1 row):** D-26-10 — stays silent, no "only N models" note. The existing `pinnedSelection`/`onlyModel` explanation (Phase 21, WR-02) already covers the single-model anthropic case; nothing new needed for the 2-row NousResearch case.

### Save flow (SET-06) — verify-only, no new interaction
`saveSettingsAction` + `getUnionServableIds` are already provider-count-agnostic (REG-07, marked Complete with a passing 4-provider test in `settings.test.ts`). This phase adds a 4-provider fixture to `groupByProvider`/`primaryAfterProviderSwitch` tests to close the end-to-end verification gap (RESEARCH Pitfall 6) — no save-path code change.

## Props & Data Contract (server → client) — ONE FIELD ADDITION

`ServableModel` (Phase 21 shape `{id, name, family, providerID, costInput, costOutput}`) gains exactly one field:

```typescript
export type ServableModel = {
  id: string;
  name: string;
  family: string;
  providerID: ModelProviderId;
  costInput: number;
  costOutput: number;
  endpoint: 'zen' | 'go' | null; // NEW (SET-03) — null for all non-opencode rows
};
```

**Derivation location (RESEARCH Pitfall 1 correction — do not follow CONTEXT.md's `settings.ts` reference):** `endpoint` is derived server-side in `src/app/(dashboard)/settings/page.tsx`'s existing `trimRow` function, from the matched catalog row's `providerID` (`'opencode-go'` → `'go'`, else `'opencode'` scope → `'zen'`), valid only when the CALLER's logical provider is `'opencode'`. `trimRow` is shared between the per-provider and union computation, so the field flows into both the provider-scoped primary picker and the union fallback picker from a single change point. `settings.ts` (the Server Action) needs ZERO changes — its union-membership gate is already provider-count-agnostic.

Client-bundle-safety (T-17-09) unchanged: `model-picker-logic.ts` keeps its type-only `ModelProviderId` import; `catalog.json` never reaches the client; the new `endpoint` field is plain derived data threaded through the existing props boundary, same as `family`/`providerID` were in Phase 21.
