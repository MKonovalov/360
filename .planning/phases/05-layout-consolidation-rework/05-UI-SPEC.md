# Phase 5 — UI Design Contract

> Visual and interaction contract for the Layout Consolidation + Rework (Company + Persona explorers move from side-by-side master-detail to a stacked, full-width, single-expand accordion table). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Inheritance notice:** This phase is a **rework of existing UI**, not a new surface. The design system (shadcn preset, typography scale, spacing scale, color palette, copywriting voice) is inherited verbatim from `02-UI-SPEC.md` (Company Explorer) and `03-UI-SPEC.md` (Persona Explorer), confirmed against currently-shipped code (`src/components/companies/*.tsx`, `src/components/ui/table.tsx`, `src/components/ui/button.tsx`, `components.json`). Nothing below re-derives an already-answered question — this document adds the **new interaction contract** (accordion expand/collapse, close control, keyboard roving-tabindex, scroll behavior) that `05-CONTEXT.md`/`05-RESEARCH.md` require but that didn't exist as a design question in Phase 2/3.

## Spacing Scale

Inherited verbatim from `02-UI-SPEC.md`/`03-UI-SPEC.md`, confirmed against shipped code:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding, chevron-to-name gap |
| sm | 8px | Compact element spacing (badge-to-badge gap, filter chip gap) |
| md | 16px | Default element spacing (list row internal padding, filter bar padding) |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps (page-level `p-8` container padding — no longer a list/detail gutter now that the split is gone) |
| 2xl | 48px | Major section breaks (between detail-panel sections: Firmographics / Tech Stack / Buying Signals / Linked Personas) |
| 3xl | 64px | Page-level spacing |

Exceptions (carried forward, plus one new this phase):
- List row minimum height: **48px** (`min-h-12`), unchanged.
- Empty/error-state card minimum height: **192px** (`min-h-48`), unchanged.
- Close control tap target: **32px** (`size-8`, shadcn `Button` `size="icon"`) — below the 44px mobile touch-target guideline but consistent with this app's existing dense/desktop-first icon-button sizing (`sidebar.tsx`'s `PanelLeftIcon` trigger uses the same `icon` size). Not treated as an exception needing a larger mobile-only variant — the mobile full-screen detail panel (D-07) has ample surrounding whitespace so mis-tap risk is low.

## Color

Inherited verbatim (slate neutrals + indigo-600 accent + amber signal badges):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / slate-50 (`#f8fafc`) | Page background, list surface, detail-panel surface |
| Secondary (30%) | slate-100 / slate-200 (`#f1f5f9` / `#e2e8f0`) | Sidebar background, list-row hover, card/table borders, filter-bar background, detail-panel divider border |
| Accent (10%) | indigo-600 (`#4f46e5`) | Selected/expanded row's left-border indicator, focus rings, inline text links (Persona's Current Company link, Arcpedia links) |
| Destructive | Not applicable this phase | No delete/edit/destructive actions exist in this rework (browse-only, same as Phase 2/3) |

Accent reserved for: the expanded row's `border-l-2 border-l-indigo-600 bg-indigo-50/50` indicator (unchanged class, now doubles as "expanded" state instead of "selected" state — same visual meaning, "this is the open record"), focus-visible rings on interactive rows/buttons, and inline text links. **Never** apply accent to the chevron expand-affordance icon, the close-control icon, static badges, section headers, or body text — those stay slate-400/slate-500/slate-900 per the existing convention.

**New this phase — two small additions to the existing palette, both neutral (no new hue):**
- Chevron expand-affordance icon: **slate-400** (`#94a3b8`), rotating 180° when expanded — a neutral, non-accent hint that the row is interactive, not a selection signal.
- Close-control icon (`XIcon` inside `Button variant="ghost" size="icon"`): inherits the `ghost` button variant's existing `hover:bg-muted` treatment — no bespoke styling.

## Interaction Contract (new this phase — not covered by Phase 2/3)

This section exists because Phase 5 introduces interaction patterns (accordion expand, keyboard roving-tabindex, scroll-on-expand, explicit close) that Phase 2/3's browse-only master-detail pane never needed. Locked decisions below come from `05-CONTEXT.md` (D-01 through D-07); visual specifics are this session's additions.

**Focal point:** Before expand, the primary visual anchor per row is the Name cell (chevron + entity name). After expand, the anchor shifts to the expanded detail panel — its Display-size entity name heading and the accent-bordered (`border-l-2 border-l-indigo-600`) expanded row above it — drawing the eye down into the now-visible detail content rather than leaving attention split across the still-visible list.

| Behavior | Contract |
|----------|----------|
| Row expand affordance | A `ChevronDownIcon` (16px / `size-4`, slate-400) sits immediately before the entity name text inside the existing Name cell — **not a new column** (preserves D-04's "same columns" constraint). Rotates 180° (`rotate-180` via `transition-transform`) when `aria-expanded="true"`. |
| Expand trigger | Clicking anywhere on the row, OR focusing the row and pressing Enter, toggles `selected`. Clicking/Enter on an already-expanded row collapses it (D-05 toggle behavior). |
| Expanded-row indicator | Reuses the existing selected-row accent class verbatim: `border-l-2 border-l-indigo-600 bg-indigo-50/50` (previously "selected", now "expanded" — same visual language, no new class). |
| Detail panel container | Sibling `<TableRow>` → single `<TableCell colSpan={7}>` (Company: 7 columns; Persona: match its own column count) with `p-0` to remove the default cell padding, so `CompanyDetail`/`PersonaDetail`'s own `p-8` card padding controls the internal rhythm. Add `border-t border-slate-200` on this cell (no `rounded-lg`/full border — it's now embedded in the table, not a standalone card) to visually divide it from the row above. |
| Close control | Top-right corner of the expanded detail panel (absolute-positioned within the detail panel's relatively-positioned wrapper). `Button variant="ghost" size="icon"` with `XIcon`, `aria-label="Close"`. **This exact corner is intentionally reserved** — Phase 6's "Menu" dropdown button will occupy the same top-right position later; do not let this button's placement drift or grow to conflict with that future addition (per D-05/05-CONTEXT.md explicit note). |
| Scroll-on-expand | On expand, scroll the clicked row to the **top** of the viewport (`scrollIntoView({ block: 'start', behavior: 'smooth' })`), not centered — per D-06, so the newly-revealed detail content directly below is immediately visible without further scrolling. No sticky top header exists in this app to offset against (verified — no `sticky`/`fixed top` in `layout.tsx`/`app-sidebar.tsx`), so no `scroll-margin-top` compensation is needed. |
| Focus on expand | Keep focus on the row itself after expand/collapse — do **not** move focus into the detail panel (would break continuous ArrowUp/ArrowDown row navigation per LAYT-05). Focus-visible treatment: `focus-visible:ring-2 focus-visible:ring-indigo-600 focus-visible:ring-inset` on the focused `<tr>` (indigo-600 — accent color, consistent with focus-ring usage elsewhere in this app). |
| Keyboard roving-tabindex | Exactly one row has `tabIndex={0}` (the focused row) at any time; all others have `tabIndex={-1}`. ArrowUp/ArrowDown move DOM focus to the previous/next `[data-row-id]` row (no wrap-around). Enter toggles expand/collapse on the focused row (toggle, not expand-only — matches mouse-click parity per 05-RESEARCH.md Open Question #2's recommendation). |
| Mobile (narrow viewport) | Unchanged D-07 pattern: expanding a row hides the list (`hidden md:block` on the list wrapper), showing the detail full-screen; the close control is the way back to the list on mobile (in addition to the row-toggle, which is no longer visible once the list is hidden). |
| Old detail route | `src/app/companies/[id]/page.tsx` / `src/app/personas/[id]/page.tsx` become thin `redirect()`-only pages (no new UI) — visually nothing to design, but note it here so no UI-SPEC gap gets flagged for a "missing" old detail page. |
