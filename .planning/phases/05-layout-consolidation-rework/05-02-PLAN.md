<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser URL -> `companies/page.tsx` `searchParams` | `selected` and filter params are user-controlled before `parseSelectedId`/`parseCompanyFilters` run |
| Browser URL -> `companies/[id]/page.tsx` `params`/`searchParams` | The dynamic `id` segment and any carried-over query params are user-controlled before being echoed into the redirect target |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-01 | Tampering | `companies/page.tsx`'s use of `parseSelectedId` before it reaches `CompanyList` -> `CompanyDetail` -> `getCompanyById` | mitigate | `parseSelectedId` (Plan 05-01) already returns `undefined` for non-numeric input; `CompanyDetail`'s existing `getCompanyById(id)` + `notFound()` path (unchanged this plan) handles a valid-but-nonexistent numeric id safely |
| T-5-02 | Spoofing / Tampering | `companies/[id]/page.tsx` redirect target | mitigate | Redirect target is always the hardcoded literal `` `/companies?${qs.toString()}` `` built from `URLSearchParams` — never a full user-supplied URL — so no open-redirect surface exists regardless of what values are echoed into the querystring |
| T-5-03 | Elevation of Privilege | `companies/page.tsx`, `companies/[id]/page.tsx` | mitigate | `await requireStaffAccess();` is preserved as the first statement in both routes' bodies through this consolidation/rewrite — never removed or made conditional |

</threat_model>
