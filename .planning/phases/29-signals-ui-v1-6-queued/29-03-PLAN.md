## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigate |
|-----------|----------|-----------|-------------|-----------------|
| T-29-03-01 | Spoofing | All 6 actions | mitigate | `requireStaffAccess()` is the literal first line of every action, independent of the page's own gate — an unauthenticated caller invoking the Server Action directly (bypassing the UI) redirects before any DB call |
| T-29-03-02 | Tampering | Create/update `unknown` input (`name`, `category`, `description`, `practiceAreaId`, `buyerRoleId`, `offeringIds`, `status`) | mitigate | zod `safeParse` against `companySignalInputSchema`/`personaSignalInputSchema` before any write; `status` is constrained to `catalogStatusEnum.enumValues` (never a free string); `practiceAreaId`/`buyerRoleId`/`offeringIds` are constrained to positive integers (the query layer's FK constraints are the backstop) |
| T-29-03-03 | Tampering | A crafted `offeringIds` entry pointing at an offering outside the signal's practice area (bypassing the UI picker's own filtering) | mitigate | `insertSignalOfferingLink`'s existing query-layer guard (T-30-01, single enforcement point) rejects the mismatch with `{ok:false, reason:'practice_area_mismatch'}` — this action layer does NOT re-implement the check with different logic, it only surfaces the query layer's result verbatim (RESEARCH.md Known Threat Patterns) |
| T-29-03-04 | Repudiation | Every write | mitigate | `createdBy`/`updatedBy` stamped from `requireStaffAccess()`'s returned `userId` on every insert/update, via the existing query-layer functions (never a bespoke `db.update()` that could skip the stamp — Pitfall 1) |
| T-29-03-05 | Information Disclosure | Server Action error responses | accept | Discriminated-union `{ok:false, reason:string}` reasons are coarse (`invalid_input`, `not_found`, `action_failed`, `practice_area_mismatch`) — no stack traces, DB error messages, or internal identifiers leak to the client; internal 3-partner tool, no additional hardening needed per project scope |
