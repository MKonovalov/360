## Typography

Declared for this phase's own markup (page title, table cells, filter labels, empty/error states, form labels). Sizes and weights below are the exact values already in production use elsewhere in the app (`reviews/page.tsx`, `review-queue.tsx`, `company-list.tsx`) — reused verbatim, not invented.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (font-normal) | 1.5 |
| Label | 12px | 400 (font-normal) | 1.4 |
| Heading | 18px | 600 (font-semibold) | 1.2 |
| Display | 24px | 600 (font-semibold) | 1.2 |

**Weights: exactly 2** — `font-normal` (400) and `font-semibold` (600). No `font-medium`/`font-bold` in any component authored for this phase.

**Documented vendor exception:** the vendored `SheetTitle` primitive (`src/components/ui/sheet.tsx:109-123`) ships with `text-base font-medium` (16px/500) baked into its own className — this phase does NOT edit `sheet.tsx` (out of scope), so the Sheet form title inherits that vendor default. Do not override it with a `className` prop hack; treat it as an accepted third-weight exception scoped to that one vendored slot only. Everything else authored in this phase (page `<h1>`, table headers/cells, filter labels, empty/error states, Sheet body field labels, button labels) uses only the 2 weights above.

Mapping to this phase's elements:
- Display (24/600/1.2): `/signals` page `<h1>` — verbatim `text-[24px] font-semibold leading-[1.2] text-slate-900` (matches `reviews/page.tsx:37`)
- Heading (18/600/1.2): Empty-state heading text — verbatim `text-[18px] font-semibold leading-[1.2] text-slate-900` (matches `company-list.tsx`/`reviews/page.tsx` empty-state pattern)
- Body (14/400/1.5): Table cell text, Sheet form field values, filter labels adjacent text
- Label (12/400/1.4): Badge text (Status/Category chips), "Last updated" timestamp, helper/caption text under form fields

## Row Anatomy / Layout Notes (non-template, executor-facing)

- **Page shell:** `<div className="flex flex-col gap-12 p-8">` wrapping `<h1>` + `Tabs` — exact reuse of `reviews/page.tsx`'s wrapper.
- **List container:** `rounded-lg border border-slate-200 bg-white` wrapping the `Table` — exact reuse of `company-list.tsx`'s container treatment (do not invent a new card style).
- **Filter bar:** `flex flex-wrap gap-3` row of `Select`s + a text `Input` for free-text search, placed above the `Table`, inside the tab panel but above the list container — mirrors `CompanyFilters`'s `EnumFilterSelect` pattern exactly, including nuqs `useQueryState` + `parseAsStringEnum` with `{ shallow: false }`. Practice Area defaults to "All" (no pre-filter forced) per spec §4.2, with GBS simply appearing first/normally in the option list since it is the only populated practice area today (D-05).
- **Table columns — Company Signals:** Name, Category, Practice Area, Linked Offerings (count, expandable — a small inline disclosure, e.g. a `Badge` showing the count that expands the row or reveals a tooltip on click; keep to the existing `ExplorerAccordionTable`'s chevron-rotate visual idiom ONLY as inspiration for the expand affordance, do not reuse that component itself per D-06), Status, Last updated.
- **Table columns — Persona Signals:** same six, plus Buyer Role inserted after Category (or wherever reads best next to Category — planner's call, not a hard requirement).
- **Row actions:** two `Button`s per row, right-aligned in a trailing cell — `Edit` (`variant="outline" size="sm"`, opens the `Sheet` in edit mode) and `Archive` (`variant="outline" size="sm"`, opens the Dialog confirm above). Archived (`status='retired'`) rows still render in the list (never removed) — consider a slightly muted row treatment (e.g. `opacity-70` or a `Badge variant="outline"` "Retired" label) so archived rows are visually de-emphasized without being hidden.
- **Sheet form field order — Company Signal:** Name → Practice Area → Category → Description → Linked Offerings (checkbox list) → Status. **Persona Signal:** same, with Buyer Role inserted directly after Practice Area (required field, fail fast before the optional-feeling fields below it).
- **Tabs default:** Company Signals tab is the default/first tab (spec §4.2 lists Company Signals first throughout).
