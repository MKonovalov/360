<task>
  <name>Task 1: EnrichmentReviewDialog client component</name>
  <steps>
  - `'use client'`. Props: `{ entityType: 'company'|'persona'; recordId: number; open: boolean; onOpenChange: (o:boolean)=>void }`. (Or expose a self-contained trigger — pick the composition that matches how ExplorerMenu items dispatch; prefer a controlled dialog opened by the menu item's onSelect.)
  - On open: call `runEnrichment(entityType, recordId)`; hold loading / error(reason) / plan states.
  - Loading → spinner/"Enriching…". Error → readable copy per reason (not_configured → "Apollo enrichment isn't configured", no_match → "Apollo found no match", no_match_key → "Add a domain/email to this record before enriching", http_*/network → "Enrichment failed, try again"). Empty plan → "Already up to date".
  - Plan → a table: columns Field | Current | Incoming | Confidence | ✓. Each row is a controlled checkbox; `fill` rows default checked, `conflict` rows default unchecked (visually flag conflicts). Confidence cell shows the number or `—`.
  - Footer: Cancel (closes, writes nothing) + Commit. Commit builds `accepted` from checked rows (`{ [field]: incomingValue }`), calls `commitEnrichment`, on `{ok:true}` closes the dialog; on failure shows the reason. Disable Commit while pending / when zero rows checked.
  - Reuse `src/components/ui/dialog.tsx` (Phase 7) and existing checkbox/button primitives; match the visual language of import-wizard steps.
  </steps>
