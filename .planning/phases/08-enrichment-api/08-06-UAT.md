## Defects Found And Fixed During UAT

1. Apollo returns HTTP 200 with `{}` for an organization no-match. The response schema incorrectly required the `organization` key and surfaced `invalid_response`; the regression test now expects `no_match`, and the envelope keys are optional.
2. Apollo returned 171 technology names for `apollo.io`. The review proposal caps `techStack` at 100, so the mapper now deduplicates and caps the list at 100 before proposal creation. Regression coverage was added.
3. Apollo's `people_match` scope is unavailable on the configured key (HTTP 403). Persona enrichment was moved to Prospeo (`POST /enrich-person`); live calls confirmed match (`200`), no-match (`400` + `error_code: NO_MATCH`), and rate limit (`429`) semantics. Regression tests cover all three.
4. Prospeo exposes seniority on the current `job_history` entry, not the top level; `prospeoMapPersona` now reads the `current: true` entry with a top-level fallback.
5. Persona-detail menu gated `canEnrich` on `APOLLO_API_KEY` and several dialogs named Apollo; the persona path now gates on `PROSPEO_API_KEY` and all enrichment copy is provider-neutral.
