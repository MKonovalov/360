  </read_first>
  <action>
    Create 'use client' ImportWizard({ entityType }: { entityType: 'company' | 'persona' }). Hold useState for step: 'upload' | 'map' | 'validate' | 'done' (initial 'upload'), and useState slices for the data each step's callback hands back: uploadResult (batchId, headers, suggestedMapping, sampleRows), validateResult (counts, errorReport), commitResult (created, updated, errored) — all typed to exactly the shapes Plans 07-07/07-08's components already define, no re-declaration of a separate parallel type.
    Render the page header ("Import Companies" or "Import Personas", entity-specific per UI-SPEC) and ImportStepIndicator currentStep={step} above the step content. Render UploadStep when step === 'upload' with onUploaded={(result) => { setUploadResult(result); setStep('map'); }}. Render ColumnMappingStep when step === 'map' (passing batchId/headers/suggestedMapping/sampleRows from uploadResult, plus entityType) with onValidated={(result) => { setValidateResult(result); setStep('validate'); }}. Render ValidationPreviewStep when step === 'validate' (passing batchId from uploadResult, counts/errorReport from validateResult, entityType) with onCommitted={(result) => { setCommitResult(result); setStep('done'); }}. Render DoneStep when step === 'done' (passing commitResult as result, entityType).
    Add a "Start over" text link visible on every step (per UI-SPEC's forward-only navigation decision — no back-navigation in v1) that resets step back to 'upload' and clears all held result state, letting staff restart with a fresh upload without a page reload.
  </action>
  <acceptance_criteria>
    - ImportWizard's client-side state includes only step, batchId (nested in uploadResult), and each step's small returned result objects — never a raw parsed-rows array or the full rawCsv text
    - Each of the 4 step components is rendered exactly once, gated by the current step value, with no back-navigation controls beyond "Start over"
    - The page header text is entity-specific ("Import Companies" vs "Import Personas"), not a generic "CSV Import" string
  </acceptance_criteria>
