# Phase 7 — UI Design Contract

> Visual and interaction contract for CSV Import (Menu → Import upload wizard for Companies/Personas with column/enum mapping, partial-commit validation, dedup, template download, and import history/rollback). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Inheritance notice:** The design system (shadcn preset, typography scale, spacing scale, base color palette, copywriting voice) is inherited verbatim from `02-UI-SPEC.md`/`03-UI-SPEC.md` (Company/Persona Explorers), `05-UI-SPEC.md` (Layout Rework), and `06-UI-SPEC.md` (Menu + Start Page), confirmed against currently-shipped code (`src/app/globals.css`, `components.json`, `src/components/ui/*.tsx`, `src/components/dashboard/*.tsx`). This document does not re-derive spacing/typography/base-color — it adds the genuinely new surfaces this phase introduces: (1) a 4-screen upload wizard (Upload → Map → Validate & Confirm → Done), (2) a file-upload dropzone (first file input in the app), (3) a column/enum-value mapping table, (4) a partial-commit validation/error report surface, (5) an import-history table with this app's **first real destructive action** (rollback), which requires installing shadcn's `dialog` primitive for the confirmation step (D-16).

## Spacing Scale

Inherited verbatim from `02/03/05/06-UI-SPEC.md`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding, step-indicator connector gap |
| sm | 8px | Compact element spacing, step-indicator pill padding |
| md | 16px | Default element spacing (mapping-table row padding, history-table row padding) |
| lg | 24px | Section padding, stat-mini-card padding (reused from Start Page) |
| xl | 32px | Layout gaps (page-level `p-8` container padding — unchanged) |
| 2xl | 48px | Major section breaks (between step indicator and step content; between counts row and error table) |
| 3xl | 64px | Page-level spacing |

Exceptions (new this phase):
- Upload dropzone minimum height: **192px** (`min-h-48`), consistent with this app's existing empty/error-state card minimum height — the dropzone reads as an empty-state-shaped affordance, not a bespoke size.
- Dropzone border: **2px dashed** (`border-2 border-dashed`) — the one deliberate deviation from the app's default `border` (1px solid) card language, needed to signal "drop target" per standard file-upload convention; border color/radius otherwise match existing cards (`rounded-lg border-slate-300`).
- Focused wizard steps (Upload, Done) use a centered `max-w-xl mx-auto` container — narrower than the app's default full-width `p-8` page shell — because these two steps are single-focal-point screens (one dropzone; one summary), not tables. The Map and Validate & Confirm steps use the app's standard full-width `p-8` shell (no `max-w`) because their mapping/error tables need horizontal room, matching `/companies`/`/personas`' existing table-page width.
- Rollback confirmation Dialog: shadcn's default `Dialog` sizing (`max-w-lg` per the vendored primitive) — not overridden.

## Typography

Inherited verbatim — no new typographic role is introduced:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | Regular (400) | 1.5 |
| Label | 12px | Regular (400) | 1.4 |
| Heading | 18px | Semibold (600) | 1.2 |
| Display | 24px | Semibold (600) | 1.2 |

Usage this phase:
- Wizard step title ("Upload CSV", "Map Columns", "Validate & Confirm", "Import Complete") → **Heading** (18px/600), same role as detail-panel section headers.
- Step-indicator pill labels ("Upload", "Map", "Validate & Confirm", "Done") → **Label** (12px/400).
- Done-screen and validate-step count numbers (Created / Updated / Errored / Skipped) → **Display** (24px/600), identical role to the Start Page's stat-card numbers — same component, same visual weight, so a staff member reads "3 created" with the same instant legibility as "12 Companies" on the dashboard.
- Dropzone primary copy ("Drag and drop your CSV, or click to browse") → **Body, font-medium** (14px/500 — the one place this phase borrows the existing `font-medium` treatment already used for list-row primary text/company names, signaling this is the dropzone's main actionable label).
- Dropzone helper copy ("Only .csv files, up to 5MB") → **Label** (12px/400, slate-500).
- Mapping-table "CSV Column" cell → **Body, font-medium** (mirrors `TableCell className="font-medium"` already used for the Name column in `company-list.tsx`).
- Mapping-table "Sample Value" cell → **Label** (12px/400, slate-500, truncated with `truncate`).
- Error-table "Row" cell → **Body, font-medium, slate-900** (same weight convention as any primary identifying cell in this app's tables).
- Error-table "Reason" cell → **Body** (14px/400, slate-600 — one shade darker than Label's slate-500, since this is the actionable content of the row, not a caption).
- History-table cells (Date, Entity, Uploaded by, Counts, Status) → **Body**, same weight/role as every other data table in the app (`company-list.tsx`, `persona-list.tsx`).

No third weight, no fifth size introduced.

## Color

Inherited verbatim (slate neutrals + indigo-600 accent + amber warning):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white / slate-50 (`#f8fafc`) | Page background, dropzone background, stat-mini-card surface, table surface |
| Secondary (30%) | slate-100 / slate-200 (`#f1f5f9` / `#e2e8f0`) | Table borders, dropzone border (`slate-300`), history-table row hover, step-indicator connector line |
| Accent (10%) | indigo-600 (`#4f46e5`) | Focus rings, inline text links (history-table "View" link, Done-screen "View imported companies" link), the current step's step-indicator pill (text + bottom border), dropzone's drag-active state border/background tint |
| Destructive | shadcn `--destructive` token (CSS-variable-driven, `oklch(0.577 0.245 27.325)` per `globals.css` — resolves to a standard red) | **First real use in this app.** Applied exclusively via the already-vendored `Button variant="destructive"` (Rollback trigger + Dialog's "Roll back N records" confirm button) and `Badge variant="destructive"` (history-table "Rolled back" status badge). Never hand-rolled as a hardcoded `red-*` Tailwind class — the destructive variant's color is already token-driven inside `button.tsx`/`badge.tsx`, so use the `variant` prop, not a bespoke class. |

Accent reserved for: focus-visible rings, inline text links, the active step-indicator pill, and the dropzone's drag-hover feedback state. **Never** apply accent to: the primary "Continue"/"Commit Import" CTA buttons (see Copywriting Contract — these use the shadcn `default` button variant, which resolves to `--primary`, a near-black neutral per this project's `radix-nova`/`neutral` preset — this is the app's **first primary/default-variant button**, since every prior phase only used `outline`/`ghost`), the mapping-table "Unmapped" badge (stays `Badge variant="outline"`, neutral), or the Done-screen count numbers (slate-900, informational not interactive, same rule as Start Page stat cards).

**Second semantic color — reused, not new:** the amber-50/amber-200/amber-800 warning-banner pattern already shipped in `company-list.tsx` (the "selected row missing" banner) is reused verbatim for: (1) the Validate & Confirm step's "N rows will be skipped" banner when `errored > 0`, and (2) a malformed-CSV parse-failure banner on the Upload step. No new hue introduced.

## Interaction Contract (new this phase)

**Focal point:** On the Upload step, the dropzone itself is the sole visual anchor (centered, `max-w-xl`, generous whitespace — nothing competes with it). On the Map and Validate & Confirm steps, the anchor shifts to the table (mapping table / error table respectively) — full width, matching the explorer list pages' own table-first hierarchy. On the Done step, the anchor returns to a centered counts summary, mirroring the Upload step's focused framing (bookending the wizard with the same narrow layout).

### Wizard shell

| Region | Contract |
|--------|----------|
| Route structure | Dedicated pages: `/companies/import`, `/personas/import` (entity type fixed by which list page's Menu → Import was clicked, D-05 — no in-wizard entity-type switcher). A shared `import_history` page per entity type (`/companies/import/history`, `/personas/import/history`), linked from both the Done step and a small "Import history" text link shown in the wizard's top-right corner on every step. |
| Step count | **4 visible screens**: Upload → Map → Validate & Confirm → Done. (`07-RESEARCH.md`'s 5-label flow — upload/map/validate/confirm/commit — describes the underlying Server Actions, not 5 mandated screens; Validate and Confirm are combined into one screen since D-12's counts *are* the confirmation surface, and Commit is a non-destructive action within that same screen, needing no separate confirm step.) |
| Step indicator | A horizontal row of 4 pills (`Badge`-styled, `rounded-4xl`) connected by a thin `slate-200` line, positioned above the step content, below the page header. Completed steps: slate-500 text + `CircleCheckIcon` (slate-400). Current step: indigo-600 text + `border-b-2 border-indigo-600`. Upcoming steps: slate-400 text, no icon. No back-navigation between steps in v1 (matches `07-RESEARCH.md` Open Question #2's "leave as planning-level UI decision" — resolved here as forward-only with a "Start over" text link on every step, simpler than reconciling stale mapping state on back-navigation). |
| Page header | Heading-style page title: **"Import Companies"** / **"Import Personas"** (entity-specific, not "CSV Import" generically — matches this app's existing entity-scoped page-title convention on `/companies`/`/personas`). |

### Upload step

| Behavior | Contract |
|----------|----------|
| Dropzone | `rounded-lg border-2 border-dashed border-slate-300 bg-slate-50 p-12 text-center`, `min-h-48`. Hover: `border-slate-400`. Drag-active: `border-indigo-600 bg-indigo-50/50` (the one deliberate accent use on this step — direct visual feedback that a drop will register). `UploadIcon` (`size-8 text-slate-400`) centered above the dropzone copy. Clicking anywhere in the dropzone opens the native file picker (hidden `<input type="file" accept=".csv">`). |
| Template download | `Button variant="outline"` with `DownloadIcon`, positioned directly below the dropzone, `mt-4` — always visible regardless of upload state, so staff can grab the correct template before preparing their file. |
| On valid file selected | Auto-submits to the upload Server Action (no separate "Upload" click needed beyond the file selection itself) and advances to the Map step on success — minimizes clicks, consistent with this being the phase's single declared Primary CTA (the click *is* the CTA). |
| On parse failure | Dropzone stays on-screen; the parse-failure error banner (Copywriting Contract) renders above it in the existing amber-50/amber-200/amber-800 pattern; staff can immediately retry without navigating away. |

### Map step

| Behavior | Contract |
|----------|----------|
| Layout | Full-width `p-8` shell (no `max-w`), reusing `Table`/`TableHeader`/`TableBody`/`TableRow`/`TableCell` verbatim. |
| Table columns | **CSV Column** (Body, font-medium) · **Sample Value** (Label, slate-500, `truncate max-w-48`) · **Maps To** (`Select` — options: schema field names + a `"— Don't import —"` null option, pre-selected via `suggestColumnMapping`'s alias match; unmatched columns show the "Unmapped" outline badge instead of a pre-selection, forcing an explicit staff pick per D-08). |
| Enum-value sub-mapping | For any column mapped to an enum field (`revenue_band`, `ownership_type`, `seniority`), an expandable row (`ChevronDownIcon` toggle, same rotation treatment as the accordion table's expand chevron from Phase 5) reveals a nested 2-column mini-table: raw CSV value → `Select` of valid enum values, pre-filled via `suggestValueMapping`'s alias match, unmapped raw values shown with the same "Unmapped" outline badge. |
| Continue | `Button variant="default"` (near-black, per `--primary` — this app's first default-variant button) reading **"Continue to Validation"**, disabled until every enum column's every distinct raw value has an explicit mapping selection (never silently defaults an unmapped enum value into commit). |

### Validate & Confirm step

| Behavior | Contract |
|----------|----------|
| Layout | Full-width `p-8` shell. Counts row first, then (conditionally) the error banner + error table, then the Commit button. |
| Counts row | 3 stat-mini-cards in a `grid grid-cols-1 gap-4 sm:grid-cols-3` — identical visual component to the Start Page's stat cards (`rounded-lg border border-slate-200 bg-white p-6`, Label caption above Display number): **"Will create"**, **"Will update"**, **"Errors"**. |
| Error table (shown only if `errored > 0`) | Amber warning banner (Copywriting Contract) directly above a `Table`: **Row** (Body, font-medium, slate-900) · **Reason** (Body, slate-600). "Download error report" outline button top-right of this table section. |
| Commit | `Button variant="default"` reading **"Commit Import"** — always enabled if `created + updated > 0`, even when `errored > 0` (partial commit, IMPT-03 — a bad row never blocks the rest). If `created + updated === 0` (every row errored), the button is disabled with helper text "Fix the errors above before importing." |

### Done step

| Behavior | Contract |
|----------|----------|
| Layout | Centered `max-w-xl mx-auto` (mirrors the Upload step's framing). `CircleCheckIcon` (`size-8`, slate-900 — success is informational here, not an accent moment) above the "Import complete" heading. |
| Counts | Display-size numbers per Copywriting Contract's summary line — computed from **actual** commit-time outcomes (Pitfall 5 in `07-RESEARCH.md`), never the validate-step's predicted counts re-displayed. |
| Links | "View imported {companies/personas}" and "View import history" text links (indigo-600), stacked `space-y-2` below the counts. |

### Import History page

| Behavior | Contract |
|----------|----------|
| Layout | Full-width `p-8` shell, matching `/companies`/`/personas`' existing table-page structure — this page reuses that same page shell, not a new one. |
| Table columns | **Date** · **Entity** (Company/Persona) · **Uploaded by** · **Created** · **Updated** · **Status** (`Badge`: "Committed" secondary / "Rolled back" destructive) · **Actions** (Roll back button, hidden once status is fully "Rolled back"). |
| Empty state | Reuses the app's standard empty-state card (`min-h-48 rounded-lg border border-slate-200 bg-white p-8 text-center`) with the Copywriting Contract's "No imports yet" heading/body. |
| Rollback trigger | `Button variant="destructive" size="sm"` reading "Roll back", per row — opens the confirmation `Dialog`. |
| Rollback confirmation Dialog | shadcn `Dialog` (new this phase). On open, calls the read-only `previewRollback` action to populate the dynamic N/M counts (Copywriting Contract) before rendering — a brief loading state inside the Dialog body (`Skeleton`, already vendored) is acceptable rather than blocking the Dialog's open animation. Confirm executes `executeRollback` and closes the Dialog on success, updating the row's status in place (no full page reload). |
| Race-condition tolerance | Per Pitfall 4/5 in `07-RESEARCH.md` (no transactions on `neon-http`), the executed rollback's actual N may differ slightly from the previewed N if a dependent row was added in between — the post-rollback inline confirmation copy always reports the **actual** executed counts, never re-displaying the pre-check numbers. |
