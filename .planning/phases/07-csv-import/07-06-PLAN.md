|----------|--------------|
| Client browser -> every action in import.ts | Server Actions are directly callable even without a Route Handler; any client can invoke uploadImportFile/commitImportBatch/executeRollback directly, bypassing the wizard UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02 | Elevation of Privilege | Any of the 6 actions called by an unauthenticated client | mitigate | Every exported function calls requireStaffAccess() as its first statement, before any file read, DB read, or DB write — an unauthenticated caller is redirected server-side with no side effect |
| T-07-03 | Spoofing | createdBy (import_batch) / rolledBackBy-style audit fields | mitigate | userId is derived exclusively from requireStaffAccess()'s return value inside uploadImportFile/executeRollback, never accepted as a caller-supplied parameter — matches the established recordView convention |
| T-07-04 | Information Disclosure / DoS | A malformed or oversized CSV crashing uploadImportFile | mitigate | The csv-parse call is wrapped in its own try/catch returning a structured { error } object; a feature-scoped 5000-row cap (Pitfall 3) backstops the global 5mb bodySizeLimit |
| T-07-05 | Tampering / Data Loss | executeRollback deleting a row that gained a dependent Signal/company_persona_role after previewRollback's pre-check | mitigate | executeRollback re-runs findRollbackableRows immediately before deleting (race-safe re-check) and additionally catches a per-row Postgres 23503 FK violation as a skip rather than an error, per Pitfall 4's no-transactions-on-neon-http constraint |
| T-07-06 | Elevation of Privilege | Any authenticated staff member can commit or roll back any batch | accept | Matches this project's existing binary access model (no roles system); explicitly accepted per D-15/REQUIREMENTS.md ACCS-01 deferral |
| T-07-07 | Tampering | A client sending an incomplete valueMapping (missing an entry for a raw enum value actually present in the file) | mitigate | validateImportBatch treats any enum-typed field whose raw value has no corresponding valueMapping entry as an explicit UNMAPPED_ENUM_SENTINEL value, which fails Zod's enum validation and surfaces as a normal per-row error in errorReport — an incomplete/inconsistent client payload can never silently commit a blank enum field (checker Blocker 2's server-side backstop, on top of the Map step UI's own Continue-button gating) |
</threat_model>
