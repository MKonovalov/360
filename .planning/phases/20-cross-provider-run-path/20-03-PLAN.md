| runAgent throw → analyzeCompany catch | Provider errors map to structured reasons; genuine failures propagate fail-loud |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-07 | Information Disclosure | missing-key reason in the not_configured result | mitigate | Only the KEY NAME surfaces (`missingKey: 'OPENROUTER_API_KEY'` — a constant, server-side string); the key VALUE is never read into any response; the gate is pure env.ts reads (`z.string().optional()` non-PUBLIC_ server-only vars, never logged); D-20-04 keeps the surface minimal (no Settings UI in Phase 20) |
| T-20-08 | Spoofing | gate bypass / lazy per-hop key check | mitigate | The ALL-or-nothing check runs ONCE at analyzeCompany entry on the RESOLVED chain (D-20-02), before any provider SDK interaction — mid-chain key surprises are structurally impossible (the loop performs no env reads); unknown chain ids (null provider) are skipped but the union servable gate upstream already excludes non-servable ids |
| T-20-09 | Information Disclosure | billing/rate_limited reason strings | mitigate | Message values are fixed server-side constants ('provider credits exhausted', 'openrouter platform rate limit', 'upstream provider rate limit'); the raw provider error text never crosses in these cases (the pre-existing `String(err)` 502 catch-all at route.ts:61 is out of scope per D-20-11) |
| T-20-SC | Tampering | npm/pip/cargo installs | accept | No installs in this plan — no package.json changes; both provider keys already declared in env.ts (Phase 19 REG-02) |
