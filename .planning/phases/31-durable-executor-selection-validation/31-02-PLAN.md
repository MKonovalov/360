<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff browser → proof routes | An authenticated browser can request only a new synthetic proof, never lifecycle authority or executor metadata. |
| route → Workflow DevKit | A route dispatches a scalar application ID to an asynchronous executor. |
| workflow step → database | Retried/replayed steps attempt guarded lifecycle mutations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-03 | Spoofing / Elevation | proof start/status routes | mitigate | Call `requireStaffAccess()` first in both routes; derive actor and proof identity server-side; route tests assert auth-first behavior. |
| T-31-04 | Tampering | route/workflow argument boundary | mitigate | Accept no client executor/status fields and call `start` with `[applicationRunId]` only; steps reload the row and guarded queries decide transitions. |
| T-31-05 | Tampering / Repudiation | retry, recovery, reconciliation, and completion | mitigate | Use bounded RetryableError/FatalError semantics, expected-state/lease/reconciliation predicates, one-time recovery and reconciliation ceilings, safe reconciliation failure, and immutable events; Local World tests run before deployment proof. |
| T-31-06 | Information Disclosure / Cost abuse | synthetic workflow | mitigate | Make proof deterministic and prohibit imports/calls to agent loops, provider SDKs, Firecrawl, prospect data, and AI UI paths; integration test scope proves no real analysis behavior. |
| T-31-SC | Tampering | installed workflow packages | mitigate | Consume only Plan 31-01's research-approved pinned packages; no suspicious dependency checkpoint is required. |
</threat_model>
