## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server page → client form | Props are server-computed from the DB + committed snapshot; the client never fetches or independently sources this data |
| form → saveSettingsAction | Untrusted client state crosses here — the action (plan 17-02) re-validates everything; the form's gates are UX, not security |
| client bundle | Any client-side import of catalog.ts would ship the 1131-row catalog.json to the browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-07 | Information disclosure | `/settings` page | mitigate | `await requireStaffAccess()` first statement (belt-and-suspenders alongside the (dashboard) layout gate, reviews precedent) — per-user config renders only for the authenticated owner; the row is keyed by the session userId |
| T-17-08 | Tampering | stale-value save bypass | mitigate | Save `disabled` while any stale saved value is present (D-10/D-11, client UX) AND the action re-validates every id against the servable set server-side (plan 17-02 T-17-03 backstop) — a bypassed client still cannot persist a non-runnable model |
| T-17-09 | Tampering | client bundle leakage | mitigate | The form and page receive server-computed `servableModels`/`defaultPrimary` props only; zero imports of `@/lib/models/catalog` in client code (grep gate in Task 2) — catalog.json (CAT-04 server-side source) never enters a client bundle |
| T-17-10 | Information disclosure | catalog data exposure | accept | Model ids, names, and costs are public catalog data (no secrets, no env keys in the form or action — security note); the D-04 footer date is likewise public. No PII is rendered beyond the user's own model config |
| T-17-SC | Tampering | npm/pip/cargo installs | n/a | Zero install surface — no packages installed by this plan (17-UI-SPEC line 29). No slopcheck gate needed. |
