# Phase 17 — UI Design Contract

> Visual and interaction contract for the Settings page (per-user AI model configuration: primary model + up to 2 ordered fallbacks, saved via a zod-validated Server Action), plus the `settings` NavKey/sidebar/ExplorerMenu nav wiring. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase does **not** introduce a new visual system. It extends the exact contracts already shipped: the Reviews page pattern (`src/app/(dashboard)/reviews/page.tsx` + `src/app/actions/reviews.ts` + `review-queue.tsx`), the v1.2 sidebar tokenized panel, and the established 04-UI-SPEC typography/color/spacing tokens. Every token below is confirmed against live code. No user questions were needed: 17-CONTEXT.md's decisions (D-01–D-15) plus the existing codebase fully determine this contract. The one open Claude's-discretion item (D-04 footer derivation) is resolved below with rationale.

## Spacing Scale

8-point scale, reused verbatim from the existing contract. Page container matches Reviews exactly (`flex flex-col gap-8 p-8`; the reviews container uses `gap-12` — this page uses `gap-8` because the form card is the only major block below the h1).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps inside buttons, `gap-1`/`gap-1.5` icon-to-label spacing |
| sm | 8px | `gap-2` between select row and arrow/remove controls, `gap-2` in button groups |
| md | 16px | `gap-4` between form blocks, `p-4` empty-state callout padding |
| lg | 24px | `p-6` form-card padding, `gap-6` between primary and fallback sections |
| xl | 32px | Page padding `p-8` (reviews page container verbatim) |
| 2xl | 48px | `gap-8` page-level spacing between h1 and card (see note) |
| 3xl | 64px | Not used this phase |

Exceptions:
- **12px (`gap-3` / `space-y-3`)** — compact card element rhythm, already the established reviews-card interior spacing (`review-queue.tsx` `space-y-3`); reuse between fallback rows and in card footers (`pt-3`).
- **Icon-only button targets: 32px** (`Button size="icon"` = `size-8`) for the up/down/X controls — a full 32px target per WCAG 2.5.8, no smaller `icon-sm` variants.

## Color

Content area: the established slate/white split from every existing page (not the CSS-variable palette — the app components consume `slate-*` + `indigo-600`; the `--primary` near-black is what the default Button variant renders).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white `#ffffff` | Page background, form card surface (`bg-white`) |
| Secondary (30%) | slate-100 `#f1f5f9` / slate-200 `#e2e8f0` | Card borders (`border-slate-200`), section divider (`border-slate-100`), muted text (`text-slate-500`/`text-slate-600`) |
| Accent (10%) | indigo-600 `#4f46e5` | Reserved for the existing inline-link pattern only — the settings page is expected to have no links, so likely unused this phase |
| Destructive | red-600 `#dc2626` (text only) | Inline save-error and stale-row warning text (`text-red-600`) — no destructive-filled buttons |

Accent reserved for: the existing inline-link treatment (indigo-600 text links) — and nothing else. **The Save button is NOT accent-colored**: it uses the app's dark primary button variant (`bg-primary text-primary-foreground`, near-black), matching the Accept button precedent in `review-queue.tsx`. Never apply indigo to section headings, labels, option rows, the empty state, or the footer — those stay slate.

**Sidebar (new Settings item):** token-only, per the v1.2 locked contract — the item inherits the scoped `[data-sidebar="sidebar"]` block (`#fbfcfd` panel, `#333333` foreground, `#909090` active pill, `#e5e7eb` hairline, `--sidebar-accent` hover). Zero new tokens, zero edits to `sidebar.tsx`.

## Interaction Contract

### Nav wiring (SET-01)

1. **`nav.ts`**: `NavKey` grows `'settings'`. `getActiveNavKey` gains `if (pathname === '/settings') return 'settings';` — exact match only (leaf page, no detail routes; keep the sibling-prefix guard discipline).
2. **`sidebar-collapse.ts`**: `getNavTooltipLabel` maps `'settings'` → `'Settings'` (add to the label map; the reviews branch stays special-cased).
3. **`app-sidebar.tsx` Manage group**: new `SidebarMenuItem` below Reviews — `SidebarMenuButton asChild` + `<Link href="/settings">`, icon `<Settings />` (lucide, rendered at 16px by the vendored `[&_svg]:size-4`), `isActive={activeKey === 'settings'}`, `tooltip={getNavTooltipLabel('settings', pendingCount)}`, className **verbatim** from the Reviews item: `h-[30px] p-0 px-2 gap-2.5 rounded-[4px] text-[15px] font-normal`. No badge (the pending-count badge is Reviews-only).
4. **`ExplorerMenu` callers**: append `{ label: 'Settings', href: '/settings' }` to the `items` array on `src/app/companies/page.tsx` and `src/app/personas/page.tsx` (after the existing Import item). No `ExplorerMenu` component change.
5. **Pure-function tests**: `nav.test.ts` (`getActiveNavKey('/settings') === 'settings'`) and `sidebar-collapse.test.ts` (`getNavTooltipLabel('settings', 0) === 'Settings'`) — D-16 Vitest rule, these are natural test targets.

### Page (server component, Reviews pattern)

- Route: `src/app/(dashboard)/settings/page.tsx` — inside the group so the layout's auth + AppShellLayout wrap it; belt-and-suspenders `await requireStaffAccess()` first (returns `{ userId }`), then `try { settings = await getModelSettingsForUser(userId) } catch { → error card }`.
- Data passed to the form (server-rendered, never client-fetched): saved settings (`{ primaryModel, fallbackModels } | null`), `getAllowlistedServableIds(catalog)` (the runnable set — never raw catalog rows, SET-07/Phase 15 D-03), per-model `{ id, name, costInput, costOutput }` (from the snapshot's **anthropic** entries), and `catalog.generatedAt` (footer).
- Page container: `flex flex-col gap-8 p-8` + `<h1 className="text-[24px] font-semibold leading-[1.2] text-slate-900">Settings</h1>`.
- Error card: the established shape — `flex min-h-48 flex-col items-center justify-center gap-2 rounded-lg border border-slate-200 bg-white p-8 text-center` with Heading 18 + Body 14 slate-500 copy from the table above.

### Form card (client component)

Structure (single card, `rounded-lg border border-slate-200 bg-white p-6`, `flex flex-col gap-6`):

1. **Empty-state callout** (only when no saved config, SET-02): compact banner at the top of the card — `rounded-lg border border-slate-200 bg-slate-50 p-4` (muted surface, distinct from the white card it sits in) with Heading 18 "No model configuration saved" + Body 14 slate-500 next-step copy. The form still renders below it, prefilled with defaults.
2. **Heading block**: "AI Model Configuration" (Heading 18) + helper copy (Body 14 slate-500).
3. **Primary model field**: Label 12 "Primary model" above a shadcn `Select` (`SelectTrigger id="primary-model" size="default"`). Options = full servable set. When no config is saved, the trigger shows the default (`FAST_MODEL_ID` → "Claude Sonnet 4.6"). **A stale saved primary renders as a disabled `SelectItem` with the stale display name + "(no longer runnable)" inline warning below the field; Save is blocked until replaced (D-11).**
4. **Divider**: `border-t border-slate-100 pt-4` → fallback section (see below).
5. **Footer row**: `flex items-center justify-between gap-3 border-t border-slate-100 pt-3` — left: Save button (`variant="default"`, `Save changes` / `Saving…` when pending, `disabled` while pending per D-12) + inline status text to its right (`Saved.` slate-600 on success; `text-red-600` error on failure, D-13/D-14). Right: nothing (empty — reserved).
6. **Page footer** below the card: `text-[12px] font-normal leading-[1.4] text-slate-500` — `Catalog synced {date}`.

### Fallback section (D-02/D-05/D-06/D-08/D-09)

**Branches on servable-set size:**
- **Size = 1 (today's roster)**: render the muted note `No additional models available — only one model is runnable right now.` (Label 12 or Body 14 slate-500) in place of the section. No rows, no Add button. The primary picker still works.
- **Size ≥ 2 (if the D-01 haiku re-verify passes)**: full section —
  - Label 12 "Fallback models" + up to **2** rows (SET-04/Phase 17 success criteria; Phase 16 D-10 confirms the DB row may carry 2 but runAgent resolves primary + 1 after dedupe — the second fallback persists but is not attempted; that is expected, not an error).
  - Each row: `flex items-center gap-2` — `Select` (`flex-1 min-w-0`, `id="fallback-1"`/`"fallback-2"`) + three ghost icon buttons (`size="icon"`, 32px): lucide `ArrowUp` (aria-label "Move fallback up"), `ArrowDown` (aria-label "Move fallback down"), `X` (aria-label "Remove fallback"). Up disabled on row 1, down disabled on the last row.
  - **Option rules (client-enforced, D-08/D-09)**: fallback options = servable set − primary − other fallback selections. A model chosen for one slot disappears from the others' options.
  - `Add fallback` outline button (Plus icon + label) appends a new row; **disabled at 2 rows** (D-06).
  - **Reorder (D-05/D-07)**: up/down arrows perform a local array move in `useState` draft state only — **arrows never auto-persist**. No drag-and-drop anywhere.
  - **Remove (D-06)**: X removes the row from the draft. Empty fallback list is allowed and saveable.
  - **Stale saved fallback (D-10)**: disabled `SelectItem` + inline warning `This model is no longer runnable — pick a replacement before saving.`; Save blocked until replaced.
- **Dedupe backstop**: the Server Action zod/validation layer rejects `duplicate_model` and primary∈fallbacks (`invalid_model`-style) even if the client is bypassed.

### Picker row content (D-03)

Each `SelectItem` shows: model display name (Body 14, slate-900) + a muted cost caption (12px slate-500) on the same row using the vendored `SelectItem` span-gap support: `{name} · ${input} / ${output} per MTok` — e.g. `Claude Sonnet 4.6 · $3 / $15 per MTok` (snapshot anthropic entry: input 3, output 15); `Claude Haiku 4.5 · $1 / $5 per MTok` if the D-01 re-verify lands. Cost reads from the **anthropic** snapshot entry by id (`getModelDisplayName`-style lookup, matching the D-06 first-match rule). No context-window column. **Never** render a raw opencode-catalog row (SET-07).

### Save lifecycle (D-07/D-12/D-13/D-14/D-15)

1. **Draft staging**: all edits live in `useState` (primary id + ordered fallback id array). Nothing persists until Save.
2. **Save**: `useTransition` wraps the Server Action call (reviews `handleAccept` precedent). Button `disabled` while pending, label `Saving…`.
3. **Success**: inline `Saved.` slate-600 confirmation; the action calls `revalidatePath('/settings')` (reviews precedent) so the server cache reflects the persisted row on reload (SET-06). No `router.refresh()` needed — the page's server-rendered props are identical to the saved draft.
4. **Failure**: inline `text-red-600` error; **draft preserved verbatim** (D-13 — never reset the `useState` on error). Retry = press Save again (draft still staged).
5. **No navigation guard** (D-15): leaving the page silently discards the draft. No `beforeunload`, no dirty-flag prompt.
6. **Staleness gates**: Save `disabled` when a stale primary (D-11) or stale fallback (D-10) is present — the disabled option plus the inline warning explain why; replacing the value re-enables Save.

### Server Action (`src/app/actions/settings.ts`)

`'use server'`. Signature: `saveSettingsAction(input: unknown): Promise<{ ok: true } | { ok: false; reason: string }>`. Order (reviews.ts pattern, immutable):
1. `await requireStaffAccess()` → `{ userId }` — FIRST, independent of the page gate.
2. Zod-parse `unknown`: `{ primaryModel: z.string(), fallbacks: z.array(z.string()).max(2) }`.
3. Validate against the server-computed servable set (`getAllowlistedServableIds(catalog)`) — every id must be present; reject `invalid_model`.
4. Validate no duplicates and primary ∉ fallbacks (D-08/D-09 backstop) → `duplicate_model`.
5. `await upsertModelSettings(userId, { primaryModel, fallbackModels })` (atomic full-value upsert, Phase 15 — no read-modify-write).
6. On success: `revalidatePath('/settings')` → `{ ok: true }`. Any throw → `{ ok: false, reason: 'action_failed' }`.
