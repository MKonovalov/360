<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → saveSettingsAction | Untrusted arbitrary `unknown` input crosses here; every field re-validated server-side, no client state trusted |
| session → userId | The only legitimate source of the settings-row key; client input must never supply it |
| DB row → future provider call | Saved model ids eventually reach `anthropic(id)` in Phase 16's runAgent; the allowlist ∩ snapshot gate is what keeps a 404-ing id out of the DB |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-02 | Spoofing (authz) | `saveSettingsAction` | mitigate | `await requireStaffAccess()` is the FIRST statement, independent of the page gate (reviews.ts precedent) — an unauthenticated caller is redirected before any parse or write; the input schema has no userId field, and `upsertModelSettings` is keyed by the session userId only (per-user data isolation, security V3/V4) |
| T-17-03 | Tampering | model-id validation | mitigate | Every id (primary + all fallbacks) is checked against the server-computed `getAllowlistedServableIds(catalogJson)` — allowlist ∩ committed snapshot (SET-07, Phase 15 D-03) — rejecting `invalid_model`; a client-supplied "servable list" is never consulted (security V5, 404-model injection) |
| T-17-04 | Tampering | chain integrity | mitigate | `duplicate_model` backstop rejects primary∈fallbacks and repeated fallbacks (D-08/D-09) even if the client gates are bypassed — the DB can never hold a self-referencing or duplicate chain |
| T-17-05 | Information disclosure | D-01 roster re-verify curl | mitigate | `ANTHROPIC_API_KEY` is read from `.env.local` into a shell variable and used only in the curl `x-api-key` header — never echoed, printed, or committed (existence-only grep; T-09-SC model-string re-verify discipline) |
| T-17-06 | Tampering | stale/dated model ids | mitigate | The allowlist ∩ snapshot gate structurally excludes dated ids (`-20\d{6}` pinned by the catalog.test.ts assertion, Phase 15 D-02 no-invented/dated-IDs rule) — a dropped-from-roster id fails the servable-set check and returns `invalid_model` |
| T-17-SC | Tampering | npm/pip/cargo installs | n/a | Zero install surface — no packages installed by this plan. No slopcheck gate needed. |
