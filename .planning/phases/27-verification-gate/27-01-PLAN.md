<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vitest parent process → spawned child process | The child env is the ONLY mutation surface (cloned `{ ...process.env, KEY: '' }`); the parent's real dev-shell env is never touched |
| Probe script stdout → parent test assertions | The probe's stdout is the sole data channel back to the test — must carry shapes only, never secrets |
| Probe script → live NousResearch/OpenCode Zen/Go APIs | Real HTTPS calls with real API keys — genuine external network trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | Information Disclosure | `scripts/probe-nousresearch-only.ts`, `scripts/probe-opencode-only.ts` | mitigate | stdout restricted to `{ ok, modelUsed, modelChain }` only, mirroring the existing `probe-openrouter-only.ts` convention verbatim — never env values, never key material, never raw provider responses |
| T-27-02 | Tampering | Parent `process.env` during test execution | mitigate | Both new tests use a cloned `childEnv` object passed only to `spawnSync`'s `env` option — the real `process.env` is never mutated, so no other test or the developer's shell is affected |
| T-27-03 | Information Disclosure | Live API keys in `.env.local` used by the probe scripts | accept | Local dev-only `.env.local` is gitignored; the probes run only when the key is present (`describe.skipIf`), never in CI without keys |
