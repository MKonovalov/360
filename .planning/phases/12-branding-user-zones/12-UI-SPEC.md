## Open-Question Resolutions (locked this UI-SPEC — recommendation + rationale)

### Q1. User-zone trigger anatomy — **full-width `SidebarMenuButton size="lg"` row wrapped in a DropdownMenu, with the dropdown in scope**

- **Trigger:** full-width row (`SidebarMenuButton size="lg"` = h-12, primitive sidebar.tsx:480), `gap-2.5`, content = 24px avatar + display name at 15px/400. Full-width per the Exa bottom-zone anatomy (FEATURES.md: full-width pill → divider → avatar+username row).
- **Dropdown: IN SCOPE.** D4 explicitly names "the Phase 12 user-menu dropdown"; the app has **zero sign-out affordance** today (grep-verified: no `SignOutButton`/`signOut`/`useClerk` in `src/`) — this dropdown is the only in-app sign-out path this milestone. ~15 lines using vendored primitives, zero edits.
- **Items (exactly three):** ① `DropdownMenuLabel` — display name (15px/600) + "Signed in as {email}" (12px/400, `text-muted-foreground`); ② `DropdownMenuSeparator`; ③ **"Sign out"** via `SignOutButton redirectUrl="/sign-in"` inside `DropdownMenuItem asChild`. `side="top" align="start"`, `className="w-56"`.
- **Explicitly NOT included: "Manage account" item.** Verified: no `/user-profile` route exists in `src/app/` and zero `UserProfile` usage anywhere. Adding an account route is out of scope (would touch `app-shell-layout`/routing, violating the single-file diff). Clerk's hosted account management is a future, separate decision.
- **Rationale:** roadmap SC #2 mandates avatar/initials + username; D4 mandates the dropdown exists; the zero-sign-out gap is a real user-facing hole that this phase closes with a token-only, vendored-primitive mechanism. Adding a route would violate scope discipline; omitting the dropdown would leave D4 dormant and users without sign-out.

### Q2. Avatar fill treatment — **`bg-sidebar-primary text-sidebar-primary-foreground`** (12.63:1), with `user.imageUrl` taking precedence when `user.hasImage`

- **Chosen:** the initials circle is `bg-sidebar-primary` (`#333333`) with `text-sidebar-primary-foreground` (`#ffffff`) glyphs at 10px/600, 12.63:1 — the **letter-mark language** (D1's Phase-13 collapsed letter-mark uses the same pair).
- **Rejected:** `bg-sidebar-accent text-sidebar-accent-foreground` (5.91:1) — `--sidebar-accent` is semantically the *hover/active* fill. If the avatar used it, hovering the dropdown trigger (which applies `hover:bg-sidebar-accent`) would visually merge the avatar into the pressed state — the circle would read as part of the hover, not as identity. It also halves the glyph contrast for a 10px text.
- **Rationale:** symmetry between the two identity anchors (dark letter-mark box top ↔ dark initials circle bottom), strongest contrast for a 10px glyph, and clean separation from every interactive hover surface. Both options are token-only (QLTY-04 pass); the choice is semantic + contrast.
- **Image path:** plain `<img src={user.imageUrl} alt="" className="size-6 rounded-full" />` when `user.hasImage` — NOT `next/image` (zero `images.remotePatterns` config exists; Clerk avatars live on `img.clerk.com`) and NOT Clerk `<UserAvatar>` (verified: no `className` prop → BRND-04 blocker). `alt=""` is correct — the adjacent display name carries identity; the avatar is decorative.

### Q3. Feedback pill anatomy — **full-width `SidebarMenuButton asChild` with `h-9 rounded-[6px] border border-sidebar-border text-[14px] font-normal`, zero explicit hover classes, semantic `<a>`**

- **Expanded (Exa-verbatim):** full-width; `rounded-[6px]` (Exa reference radius); `border border-sidebar-border` (Exa "hover = border color" mapped to the token — `--sidebar-border` is Exa's gray-200 `#e5e7eb` exactly); 14px/400 text. **Hover is inherited from the primitive's default variant** (`hover:bg-sidebar-accent hover:text-sidebar-accent-foreground`, sidebar.tsx:469/473) — adding explicit hover classes is redundant and invites grep-gate count drift.
- **Semantics:** `<a href={FEEDBACK_MAILTO}>` where `FEEDBACK_MAILTO` is a module-level static constant (D2 verbatim). Not a `<button>`, never user-interpolated (V5/URL-injection).
- **Collapsed rail (dormant, Phase 13 prep):** **icon-only, not hidden** — a feedback channel survives in the 48px rail, honoring the "labels fade, icons stay" contract. Pre-wire: text span `group-data-[collapsible=icon]:hidden`; `Mail` icon `hidden group-data-[collapsible=icon]:block size-4` (`aria-hidden="true"` — the `<a>` carries `aria-label="Give us feedback"`, same locked string). Today `collapsible` is dormant (`offcanvas`), so the pill renders text-only exactly as Exa; Phase 13 flips to icon-only with zero rework. Tooltip wiring is Phase 13.

### Q4. Wordmark zone collapsed behavior — **fade, not hide** via `group-data-[collapsible=icon]:opacity-0 transition-opacity duration-200`

- The wordmark + org-label block (both lines in one wrapper div) gets `group-data-[collapsible=icon]:opacity-0 transition-opacity duration-200`, **matching the primitive's own label-fade contract** (`SidebarGroupLabel`: `group-data-[collapsible=icon]:-mt-8 opacity-0`, sidebar.tsx:404). Fade (not `hidden`) preserves the Phase 13 swap seam: Phase 13 replaces the faded block with the 28px letter-mark box in the same slot. No extra collapsed sizing this phase — the header is `gap-1 p-3` and Phase 13 owns rail layout.

### Q5. Divider between pill and user zone — **vendored `SidebarSeparator`**, no custom element

- Verified in source (sidebar.tsx:353-365): `SidebarSeparator` = `Separator` with `mx-2 w-auto bg-sidebar-border` — **already tokenized to exactly Exa's divider hue** (`--sidebar-border: #e5e7eb` = gray-200). Its `mx-2` (8px horizontal margins) approximates Exa's `margin: 8px 0`. Zero new classes, zero custom divider, one line. Placement: pill → `SidebarSeparator` → user row (Exa's pill → 0.6px divider → avatar+username order, FEATURES.md:23).

### Q6. Verification split — **grep-gate + unit-test dimensions automated in-phase; live-browser render = Manual; contrast audit deferred to Phase 14**

| Dimension | Owner | Detail |
|-----------|-------|--------|
| Copy/classes (BRND-01, BRND-03) | Automated grep gate | D1 copy ×2, D2 mailto ×1, `Give us feedback` ×1, token classes present |
| Identity logic (BRND-02) | Automated unit test | `src/lib/user.test.ts` — fallback-chain nullability lock (mirrors `nav.test.ts`, QLTY-01 convention) |
| Token-only purity (BRND-04, QLTY-04) | Automated grep gate | `indigo`/`amber`/hex/`dark:` = 0 in `src/components/layout/`; fence gates on 5 protected files |
| Type safety / regression | Automated | `npx tsc --noEmit`; `nav.test.ts` 11/11; `npm test`; `npm run build` |
| User-zone render, dropdown portal, sign-out round-trip | **Manual** (local `npm run dev` + real signed-in Clerk session) | Hydration (no blank-flash), avatar/initials, dropdown opens upward over light content, sign-out redirects to `/sign-in` |
| WCAG AA contrast audit + UAT matrix | **Phase 14** (QLTY-03) | Phase 12 ships no new tokens; all state pairs pre-verified in Phase 10's contract |
