# Findings

- Review follow-up confirmed that the existing `buyer_role` table had no persisted department, function, seniority, or geography selector metadata. The production fix is four nullable PostgreSQL `text[]` columns projected by `listBuyerRoles()`.
- Search template JSONB is runtime data despite Drizzle's compile-time `$type`; malformed rule or evidence JSON must be rejected before array copying. The query now returns the existing safe unavailable result (`undefined`), which resolves to `template_not_found`.
- Task 1's persisted `SearchBuyerRoleSnapshot` is intentionally `{ id, name }`. Rule and selector evidence is now a separate `buyerRoleEvidence` projection so persisted role snapshots remain contract-compatible and downstream proposal evidence is lossless.
- The fixture-gated DB integration lane remains unavailable in this environment: `TEST_DATABASE_URL` does not carry the required `phase39-fixture` marker. Drizzle check and migration artifact validation pass independently.
- Downstream candidate sanitization previously revalidated proposals only against `buyerRoleIds`, so selector-only and mixed selector resolutions were discarded despite valid launch evidence. The fix persists a typed `buyerRoleEvidenceSnapshot` with the Search run and validates each proposed rule against that immutable role-to-rule evidence map.
- Runtime validation now strictly parses persisted evidence, rejects unknown fields and malformed nested arrays, deep-freezes accepted snapshots, and cross-checks role names plus rule metadata, selector values, match mode, and explicit IDs before authorization. Focused candidate tests cover null, undeclared, and stale same-ID evidence without allowing a throw or proposal.
- Task 4 remediation keeps candidate-level salvage behavior while enforcing the packet's 25-candidate limit at the envelope boundary. Duplicate normalized candidate IDs now fail the packet before normalized candidates are returned.
- Packet canonicalization now sorts proposal rule IDs, proposals, claim source IDs, sources, claims, and diagnostics with locale-independent comparisons. Uppercase `HTTPS://` sources classify from the parsed canonical URL protocol rather than a case-sensitive raw prefix.
- Evidence evaluation now requires every supported, verified claim to reference at least one policy-eligible source even when `minimumPublicSources` is zero. Focused Search regressions pass: 17 tests across normalization and evidence suites; targeted ESLint, LSP diagnostics, and production build also pass.
- Follow-up remediation makes duplicate normalized source URL selection input-order independent by sorting normalized sources on a total locale-independent content key (`sourceId`, kind, URL, labels, and timestamps) before deduplication. Dropped source IDs alias to the deterministic winner, so claims preserve valid references and evidence counts remain unchanged.
- The new reversed duplicate-source regression failed before the fix and passes afterward; the focused normalization, matching, and evidence suites pass at 23/23. TypeScript, production build, and targeted ESLint pass. TypeScript LSP diagnostics were requested after the build but timed out despite the active server reporting alive; no diagnostic output was returned.
- A directory-level TypeScript LSP scan of `src/lib/search` completed cleanly with zero diagnostics after the per-file requests timed out.
- Search submission now requires the authenticated local run ID and initiating user, parses a strict bounded Company context, and fails with `invalid_input` before partner submission when unknown context fields are present.
- Reconciliation now computes the terminal packet hash from the same normalized Search packet used by candidate processing, preventing raw-vs-normalized replay conflicts.
- Candidate sanitization now rejects malformed persisted Buyer Role evidence even when a candidate proposes zero Buyer Roles, so malformed evidence cannot produce a Review row.
- Remediation verification passed: focused Search/Arc Agent Net tests 39/39, `npx tsc --noEmit`, targeted ESLint, per-file LSP diagnostics, and `npm run build`. Full-project ESLint still reports pre-existing unrelated errors outside the changed files. The DB integration lane remains blocked by the existing `phase39-fixture` marker requirement; the no-excuse audit could not run because Bun is unavailable and its TypeScript script cannot resolve the caller project's `typescript` module through `npx tsx`.
- Task 6 remediation now drops candidates whose claims reference missing packet sources before persistence, while preserving valid candidates and emitting `missing_source_reference` diagnostics. Strict Review projections safely omit malformed legacy rows rather than returning an invalid contract.
- Search candidate ingestion audits now have a database uniqueness constraint on `(search_candidate_id, event_type, revision)`, an explicit conflict target, and a migration cleanup that retains the lowest audit ID for pre-existing duplicates before adding the constraint.
